# 단계별 통과 시험 (LQI8) — LQR 먼저, 적분은 나중에

> 2026-11-10: 이 폴더는 `wheeled_biped/TEST/`에서 `wheeled_biped/v5_lqi/TEST/`로 옮겼다. 시나리오·지표·기준·보고서 코드는
> `wbr/bench/stage_tests.py`로 빼서 MPC 폴더(`v5_mpc/TEST/`)와 같이 쓴다. 두 폴더의 보고서는 같은 시험·같은 기준이라 줄마다 비교할 수 있다.
> 이 폴더의 `stage_common.py`는 LQI 단계(`v5_lqi/controller.py`의 `STAGES`)를 등록만 한다.

균형 제어기를 한 번에 완성하지 않고 **순수 LQR → 바깥 루프 → ∫위치 → ∫기울기** 순서로 올리기 위한 시험이다.
한 단계를 통과한 뒤 다음 단계로 넘어가고, 뒤 단계는 앞 단계의 시험을 전부 다시 통과해야 한다.

대상 로봇은 v5 CAD 로봇이다(Fusion에서 뽑은 전용 URDF `models/wheelbiped_v5`, AKE60-8 × 6, 링크 25 cm, 11.60 kg, `docs/robot_v5_model.md`). 앞은 로커 스위치 쪽이고 무릎은 뒤를 향한다. MuJoCo 폐루프로 돌린다.

**현재 판정(11-07, 링크 25 cm): 단계 4 시험 27개 중 7개가 일부 기준을 넘는다(5절 앞 "링크 25 cm 결과"). 넘어지거나 무릎이 꺾인 경우는 없다. 기준 숫자는 바꾸지 않았다.**
IMU는 실제 칩 위치에서 재고, pi3hat 펌웨어 필터 → MCU 자세 필터를 거쳐 제어기에 들어간다.
시나리오와 측정 정의는 기존 합격 판정(`docs/합격기준.md`, `wbr/bench/acceptance.py`)의 것을 그대로 쓴다.
기존 단위 테스트(`tests/`)와는 별개다. `WBR_TEST_CAD`로 전용 URDF가 없는 CAD 버전(v2~v4)을 주면 예전 upkie 경로로 돈다.

## 1. 단계

| 단계 | 균형 제어기 | `lqi_kwargs` | 이 단계에서 확인하는 것 | 파일 |
|---|---|---|---|---|
| 1 | 순수 LQR, 상태 6개 `[θ, θ̇, v − v_ref, φ, φ̇, x − x_ref]` | `q_att=None, q_pos=None` | 상태 피드백만으로 서고, 기울기·밀기에서 복귀하고, 속도 스텝을 따라간다 | `test_stage1_lqr.py` |
| 2 | 단계 1과 같음 | 같음 | 논문 Fig. 6의 나머지 네 제어기(높이, 요, 롤, 다리 벌어짐)가 균형을 해치지 않고 제 일을 한다. 무릎 결합 보상이 hip·바퀴 토크의 영향을 다리 길이에서 뺀다 | `test_stage2_outer_loops.py` |
| 3 | + ∫위치 (z3) | `q_att=None, q_pos=0.5` | 일정한 외란 아래에서 출발 위치로 돌아온다. 단계 1·2 시험 재통과 | `test_stage3_int_position.py` |
| 4 | + ∫기울기 (z2) = 현재 제어기 | `q_att=0.2, q_pos=0.5` | 일정한 외란 아래에서 실제 몸통이 수평으로 돌아온다. 단계 1·2·3 시험 재통과 | `test_stage4_int_tilt.py` |

상태 6번째(`x − x_ref`)는 코드에서 `z1 = ∫(v − v_ref)`다. 속도를 적분한 값이라 위치 그 자체이고 논문의 `x` 상태에 해당한다.
논문의 `∫x`가 z3, `∫γ`가 z2다. 코드에서는 `Plan4Config(lqi_kwargs={...})`에 위 값을 넣으면 그 단계가 된다.

## 2. 실행

`wheeled_biped/`에서 실행한다.

```
python v5_lqi/TEST/run_stages.py --stage 4 --keep-going    # 전체 제어기(현재 쓰는 시험). 보고서: v5_lqi/TEST/results/stage_report.md
python v5_lqi/TEST/run_stages.py                    # 단계 1 → 4, 실패한 단계에서 멈춤
python v5_lqi/TEST/run_stages.py --stage 1 2        # 일부 단계만
python v5_lqi/TEST/run_stages.py --keep-going       # 실패해도 끝까지
python -m unittest discover -s v5_lqi/TEST -v                            # unittest로 전부
python -m unittest discover -s v5_lqi/TEST -p "test_stage1*.py" -v      # 한 단계만
```

시드 하나에 단계 4만 약 2분 30초, 전체 약 7분(다른 실행과 동시에 돌렸을 때 잰 값). 2-16이 30 s를 돌고 필터가 스텝마다 돈다.

| 환경 변수 | 기본 | 뜻 |
|---|---|---|
| `WBR_TEST_SEEDS` | `0` | 노이즈 시드 목록, 예 `0,1,2,3,4` |
| `WBR_TEST_LATENCY_MS` | `10` | 센서 → 토크 지연 |
| `WBR_TEST_RATE` | `1000` | 제어 주기 [Hz] (200도 가능) |
| `WBR_TEST_LONG` | `0` | `1`이면 정지 시험을 합격 기준대로 60 s (기본 30 s) |
| `WBR_TEST_CAD` | v5 | 다른 CAD 버전의 `mass_properties.json` 경로 |

PowerShell 예: `$env:WBR_TEST_SEEDS = "0,1,2"; python v5_lqi/TEST/run_stages.py`

## 3. 통과 기준

공통 조건: 센서 노이즈 켬, 지연 10 ms, 1 kHz, 판정 피치는 시뮬레이터의 실제 몸통 피치.

모든 시험에 함께 붙는 기준: 넘어지지 않음, 무릎이 완전 신장 반대쪽으로 넘어가지 않음, 완전 신장까지 5 mm 이상,
바퀴·hip·무릎 토크 피크 ≤ 10 N m(AKE60 피크의 80 %), hip·무릎 rms ≤ 5 N m(정격), 바퀴 10 s rms ≤ 2.5 N m.

## 4. 합격기준.md와 다른 점

- **모터 한계**: upkie의 qdd100·mj5208 대신 AKE60-8(피크 12.5, 정격 5 N m). 포화 지속·관절 속도 기준은 넣지 않았다.
- **센서 노이즈**: 합격 기준의 노이즈는 upkie 하네스의 "참 자세 + 흰 잡음"이고 Plan 4 판정(`wbr/bench/acceptance.py`)은 그대로 그것을 쓴다. 이 폴더는 v5 시험이라 칩 위치의 자이로·가속도 노이즈를 펌웨어 필터 포팅과 MCU 자세 필터에 통과시킨다. 그래서 1-1의 피치 rms를 합격 기준 수치와 바로 비교할 수 없다.
- **정지 시험 길이**: 기본 30 s(합격 기준은 60 s). `WBR_TEST_LONG=1`로 60 s.
- **속도 스텝의 정지 뒤 정착**: 합격 판정은 정지 뒤 3 s만 돌리고 마지막 위반이 끝 1 s 안이면 미정착이라, 사실상 2 s 안에
  정착해야 한다. v5는 정지할 때 25~29 cm 나갔다가 0.13~0.16 m/s로 되돌아와 **2.1~2.2 s**가 걸린다(세 단계 모두). 이 시험은
  정지 뒤 5 s를 돌리고 정착 시간 ≤ 3 s로 판정한다. 2 s로 맞추려면 제어기를 조정해야 한다(결정 사항).
- **짐**: 0.5 kg(합격 기준 17번은 5.3 kg upkie에 0.3 kg). 로봇 질량 비로 키웠다.
- **16·17번의 피치 기준**: 합격 기준은 전 구간 이동평균 ≤ 1°다. 여기서는 적분 두 개의 역할을 따로 보려고 끝 5 s 평균을 쓴다.
- **변동 매트릭스 없음**: 질량 ±15 %, 마찰 0.5~1.0 조합은 돌리지 않는다(공칭만). 시드는 기본 0 하나.
- **추가 항목**: 무릎 꺾임과 완전 신장 여유(전 시험, 더 긴 쪽 다리 기준), 롤 기준, 주행 중 회전, 한쪽 턱, 다리 범위, 한쪽 짐, 날카로운 턱의 방향, IMU 추정 오차.
- **시험하지 않는 경우**: 4 cm 턱을 0.2~0.4 m/s로 넘기(바퀴가 끼여 약 45° 돈다, `robot_cad_v5/README.md` 6절 한계). 기준을 정한 조건은 넘어갈 수 있는 속도다.

## 7. 실기에서

같은 순서로 올린다. 단계 1의 `lqi_kwargs`로 시작해 시험 1-1~1-4를 실물로 반복하고, 통과하면 바깥 루프, 그다음 적분을 하나씩 켠다.

- 실기에는 "실제 피치"가 없다. IMU 추정 피치만 있으므로 4-2(IMU 오차)는 실물에서 직접 볼 수 없다. 수평계를 몸통에 올리거나,
  짐(4-3)과 경사(4-1)로 확인한다.
- 위치는 바퀴 오도메트리로 잰다. 바닥에 출발선을 표시해 두면 3-x를 눈으로도 확인할 수 있다.
- 요·다리 길이 게인은 이 시뮬레이션과 같은 환산값을 MCU 설정에 넣어야 한다(`ake_cad.outer_loop_gains`).
- 무릎 결합 보상도 켜야 한다(`wheel_reaction_ff=True`, 2-5·2-6의 조건). 끈 채로는 경사에서 다리가 늘어난 자세로 선다.
- 순응 롤도 켜야 한다(`roll_compliant=True`와 `ake_cad.compliant_roll_gains`의 값, 2-7~2-10의 조건). 처음에는 턱 없이 2-3부터 확인한다.
- 바퀴 속도 차 요도 켜야 한다(`kw_yaw`, `ki_yaw`, `ake_cad.yaw_wheel_damping_gains`의 값, 2-11~2-13의 조건). 처음에는 턱 없이 2-2, 2-4부터 확인한다. 실제 공기 타이어는 시뮬레이션의 단단한 타이어보다 턱을 잘 넘을 수 있으므로 낮은 턱부터 올린다.
- IMU: pi3hat은 `mounting_deg` 0, `attitude_rate_hz` 1000으로 둔다. 로봇의 앞은 로커 스위치 쪽이다. 원시 축은 +x 로봇 뒤, +y 로봇 오른쪽, +z 위이고(`R_base_to_imu` = diag(−1, −1, 1)), 수평에서 보드는 롤 180°로 읽는 것이 정상이다(hat이 위, `R_ars_to_world` = diag(1, −1, −1)). 필터에 넣을 원시값은 보드 출력에서 복원한다: 자이로 = `rate_dps − bias_dps`, 가속도 = `accel_mps2 + 9.81 × 중력(자세)`. 켜기 전에 로봇을 손으로 스위치 쪽으로 기울여 피치 부호부터 확인한다(앞으로 기울이면 + 피치).

- 서스펜션과 감속: 낮은 턱부터 올린다. 다리가 345 mm 넘게 펴지면 멈춘다(350 mm에서 무릎이 반대로 꺾인다). 200 mm 아래는 Fusion 간섭 검사 범위 밖이다.
