# v5_mpc — MPC 하나만 쓰는 v5 로봇

v5 로봇(`models/wheelbiped_v5`, AKE60-8 × 6, 링크 25 cm)의 균형 제어기를 **MPC 하나**로 두는 폴더다(2026-11-10 사용자 요청).
LQI8은 이 폴더 어디에도 없다. Plan 4의 MPC 호스트(`wbr/controllers/mpc_host`, LQI 위에서 속도 기준만 만드는 것)도 쓰지 않는다.
MPC가 MCU 안에서 LQI8 자리에 들어가 바퀴·hip 토크를 직접 낸다. 같은 일을 LQI8로 하는 폴더는 `../v5_lqi/`다.

```
호스트(50 Hz): 목표 속도·요 속도·높이 (HostEmulator)
      │
MCU(1 kHz): 상태 추정 ─▶ MPC (T, Tp) ─▶ 높이·요·롤·벌어짐 루프 ─▶ 직렬 다리 VMC ─▶ 관절 토크
```

로봇 모델, 시뮬레이터, IMU 경로, MCU와 바깥 루프 네 개(높이 PD, 요 PI, 순응 롤, 벌어짐 PD), 무릎 결합 보상은 `v5_lqi`와 같은 코드다.
두 폴더는 **MCU 안의 균형 제어기만** 다르다(11-10 사용자 선택: 바깥 루프는 같이 쓴다).

## 파일

| 경로 | 내용 |
|---|---|
| `mpc_law.py` | MPC 본체 `BalanceMPC`(예측 모델, 미리보기, 모터 토크 제약, QP)와 MCU 연결 `MpcLaw` |
| `controller.py` | `PlanV5Mpc`(v5 폐루프에서 균형 제어기만 MPC로), 기본값 `MPC_DEFAULTS`, 단계 정의 `STAGES`, `make_plan()` |
| `TEST/` | 단계별 통과 시험. `v5_lqi/TEST`와 시나리오·기준이 같다(`wbr/bench/stage_tests.py`를 같이 쓴다) |

## MPC 설계

**예측 모델**: v5 직렬 다리 플랜트를 현재 다리 길이에서 선형화한 것(`plant_serial`, LQI8과 같은 로봇 모델).
상태 `e = [θ, θ̇, v − v_r, φ, φ̇, z1 (, z2) (, z3)]`, 입력 `u = [T, Tp]`(정적 hip 토크 `Tp_ff`를 뺀 몫).
z1 = ∫(v − v_r) 위치 오차, z2 = ∫(정적 몸통 기울기), z3 = ∫z1. 적분 상태 두 개는 LQI8과 같은 식이며, 여기서는 예측 모델의 상태다.

**예측 구간**: 1 ms, 1 ms, 2 ms, 4 ms, 그다음 10 ms × 30 = 0.31 s(입력 34개). 단계 비용은 구간 길이로 가중하고, 끝 비용은 1 ms DARE 해다.
앞쪽을 제어 주기로 잘게 잘라서, 제약이 안 걸리면 첫 입력이 제어 주기의 LQR 피드백과 같아진다(바퀴 0~1 %, hip 4~16 % 차이).
처음에 10 ms 균등 구간으로 짰을 때는 hip 게인이 LQI의 60~76 %로 물러졌다.

**가중치**: Bryson 값을 v5 LQI8과 같은 숫자로 두었다(`q_θ` 0.3, `q_θ̇` 3, `q_v` 0.5, `q_φ` 0.15, `q_φ̇` 3, `q_z1` 0.2, `q_z2` 0.2, `q_z3` 0.5,
토크 가중은 로봇 무게·크기에서 `PlanV5._lqi_design`과 같은 규칙). 비교가 튜닝이 아니라 구조의 차이가 되게 하려는 것이다.

**LQR과 다른 점**
1. **선행 미리보기**: 새 속도 명령이 들어오면 기준은 0.15 s 뒤에 2 m/s² 램프 + 0.1 s 필터로 출발한다. MPC는 그 기준을 예측 구간 동안 미리 본다.
   기준과 그 기울기가 정확한 이산화에 외부 입력으로 들어간다. 그래서 로봇이 기준이 움직이기 전에 몸을 기울인다.
   기준이 움직이는 동안 z1은 LQI8처럼 멈춘다. 멈추지 않으면 출발 때 밀린 위치를 따라잡느라 선행 시간과 상관없이 속도 오버슈트가 14~38 % 났다.
2. **모터 토크 제약**: 앞 10개 입력(약 68 ms) 동안 바퀴(`T/2 ± τ_yaw/2`)와 hip·무릎 토크가 각 모터 피크의 75 %(9.4 N·m) 안에 있어야 한다.
   hip·무릎은 지금 관절각의 VMC 사상에 다리 힘, 벌어짐 토크, 무릎의 바퀴 반작용 항을 넣어 계산한다.
   다리 힘은 MCU의 다리 루프가 한 주기 전에 실제로 준 값이다(`DiabloMcu.leg_force_cmd`: 정적 지지력 + 길이 PD + 롤 + 범위 벽 + 감쇠).
   정적 지지력만 쓰면 다리가 범위 끝에 닿았을 때 무릎 토크를 작게 봐서 20 cm 턱에서 몸통이 10° 기울었다(2026-11-11 고침, `TEST/README.md` 4절).
   제약 없는 해가 모든 제약을 지키면 그 해를 그대로 쓴다(QP를 풀지 않고, 결과는 같다). 어기면 DAQP로 QP를 푼다.
   바깥 루프만으로 이미 넘은 제약은 뺀다(균형 토크로는 못 고친다).

**LQI8과 같은 점(MCU와의 약속)**: 울퉁불퉁한 바닥에서 MCU가 속도를 줄일 때 넘기는 값(`v_brake`, `v_brake_tau`, `hold_integrators`, `v_lean`)을 모두 쓴다.
`v_lean`은 감속하는 만큼 다리 기울기 목표를 뒤로 옮기는 값이다. 이것을 쓰지 않으면 감속이 LQI8의 절반이라 턱 위 속도와 날카로운 턱의 옆 이동이 기준을 넘었다(2026-11-11 고침, `TEST/README.md` 5절).

**계산량**: 다리 길이 격자(312~497 mm, 5 mm, 38점)에서 압축 행렬을 시작할 때 만들고(0.2 s), 실행 중에는 두 격자 사이를 선형 보간한다.
제약 없는 스텝은 약 50 µs(파이썬), QP는 약 0.3 ms(첫 호출 50 ms는 import).

## 선형 모델 비교 (MuJoCo 없이, 1 kHz, 센서 지연 10 ms, 기립 460 mm)

| | LQI8 | MPC |
|---|---|---|
| 0.5 m/s 스텝: 90 % 도달 / 오버슈트 / 정상 오차 | 1.23 s / 9.1 % / 0.035 m/s | 0.70 s / 7.2 % / 0.030 m/s |
| 0.5 m/s 스텝: 피치 최대 / 정지 뒤 최대 이탈 | 0.86° / 0.31 m | 1.48° / 0.25 m |
| 1 m/s 스텝: 도달 / 오버슈트 / 피치 | 1.45 s / 3.3 % / 1.57° | 0.88 s / 4.1 % / 2.39° |
| 밀기(지면 속도 0.6 m/s 충격): 이동 / 피치 / 바퀴 T / hip Tp | 0.27 m / 2.53° / 5.4 / 3.8 N·m | 0.27 m / 2.64° / 5.5 / 4.2 N·m |

제약이 안 걸리는 밀기에서는 둘이 거의 같다. 첫 입력이 같은 LQR이라서다. 차이는 속도 명령을 따라가는 방식(미리보기)과,
토크가 한계에 닿는 큰 외란에서 나온다. MuJoCo 폐루프 결과는 `TEST/README.md`에 있다.

## 실행 (`wheeled_biped/`에서)

```
python v5_mpc/TEST/run_stages.py --stage 4 --keep-going     # 전체 MPC(∫위치 + ∫기울기)의 단계 시험
python -m unittest tests.test_v5_mpc -v                      # MPC 단위 시험
python -c "from v5_mpc.controller import make_plan; p = make_plan(); p.reset(); print(p.run(2.0))"
```

설정은 `make_plan(mpc_kwargs=dict(t_lead=0.1, u_limit=0.7))`처럼 `MPC_DEFAULTS`를 덮어쓴다.
`u_limit=0`이면 제약 없는 MPC(QP 없이 명시적 해만)가 된다.

## 실기에서

- Pi 4B 500 Hz에서 제약 없는 스텝은 행렬·벡터 곱 몇 개라 여유가 있다. QP(변수 68개, 부등식 최대 120개)는 C의 DAQP로 수십 µs가 예상되지만, 실측은 아직 없다.
- 지연 보상은 넣지 않았다(LQI8도 꺼져 있다). 실기 지연을 잰 뒤 예측 모델에 입력 지연을 넣을 수 있다.
