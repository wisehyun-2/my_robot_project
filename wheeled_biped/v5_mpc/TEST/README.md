# 단계별 통과 시험 (MPC)

`v5_lqi/TEST`와 **같은 시나리오, 같은 지표, 같은 기준**으로 MPC를 시험한다. 공통 코드는 `wbr/bench/stage_tests.py`이고,
이 폴더의 `stage_common.py`는 MPC 단계(`v5_mpc/controller.py`의 `STAGES`)를 등록만 한다. 기준표, 시나리오 설명,
합격기준.md와 다른 점은 `v5_lqi/TEST/README.md` 3·4절을 그대로 따른다.

## 1. 단계

| 단계 | 균형 제어기 | `mpc_kwargs` | 이 단계에서 확인하는 것 | 파일 |
|---|---|---|---|---|
| 1 | MPC, 예측 상태 6개 `[θ, θ̇, v − v_r, φ, φ̇, x − x_r]` | `q_att=None, q_pos=None` | MPC만으로 서고, 기울기·밀기에서 복귀하고, 속도 스텝을 따라간다 | `test_stage1_mpc.py` |
| 2 | 단계 1과 같음 | 같음 | 바깥 루프 네 개(높이, 요, 롤, 벌어짐)가 MPC와 같이 제 일을 한다 | `test_stage2_outer_loops.py` |
| 3 | + ∫위치 상태 (z3) | `q_att=None, q_pos=0.5` | 일정한 외란 아래에서 출발 위치로 돌아온다. 단계 1·2 재통과 | `test_stage3_int_position.py` |
| 4 | + ∫기울기 상태 (z2) = 전체 MPC | `q_att=0.2, q_pos=0.5` | 일정한 외란 아래에서 실제 몸통이 수평으로 돌아온다. 단계 1~3 재통과 | `test_stage4_int_tilt.py` |

LQI 폴더와 단계 구성이 같고, 적분 상태가 LQR 대신 MPC의 예측 모델에 들어간다는 점만 다르다.

## 2. 실행 (`wheeled_biped/`에서)

```
python v5_mpc/TEST/run_stages.py --stage 4 --keep-going    # 전체 MPC. 보고서: v5_mpc/TEST/results/stage_report.md
python v5_mpc/TEST/run_stages.py                    # 단계 1 → 4, 실패한 단계에서 멈춤
python -m unittest discover -s v5_mpc/TEST -p "test_stage1*.py" -v
```

환경 변수(`WBR_TEST_SEEDS`, `WBR_TEST_LATENCY_MS`, `WBR_TEST_RATE`, `WBR_TEST_LONG`, `WBR_TEST_CAD`)는 LQI 폴더와 같다.

## 4. 2-19의 피치 10.1°: 원인과 수정 (2026-11-11)

**원인: 토크 제약이 다른 루프가 이미 무릎에 실은 토크를 작게 잡아서, 이미 깨진 제약을 지키려고 hip 균형 토크를 막았다.**

**수정**: MCU가 매 주기 다리별로 계산한 힘(정적 지지력 + 다리 길이 PD + 롤 + 범위 벽 + 감쇠)을 `DiabloMcu.leg_force_cmd`에 남기고, `MpcLaw.limits`가 정적 지지력 대신 그 값(한 주기 전 것)을 쓴다. MCU에는 저장 한 줄이 늘었을 뿐이라 LQI8 결과는 그대로다(단계 4 시드 0의 288건이 커밋된 보고서와 값까지 같다).

| 2-19, 시드 0 | 피치 최대 | QP 호출 |
|---|---|---|
| 고치기 전 | 10.11° | 564 |
| 고친 뒤 | 1.58° | 46 |

고친 뒤에도 QP가 46스텝 걸리는 것은 다리가 벽에 닿으면서 무릎 토크가 한계(9.38 N·m) 바로 밑을 지나가는 짧은 순간이고, 그동안 피치는 0.8° 안팎으로 변화가 없다. 단계 4 전체에서는 2-19만 달라졌다(11건 → 10건).

아래는 고치기 전에 원인을 찾으려고 같은 시험을 조건만 바꿔 돌린 결과다(시드 0):

| 조건 | 피치 최대 | QP 호출 |
|---|---|---|
| LQI8 | 1.54° | — |
| MPC 기본(`u_limit` 0.75) | 10.11° | 564 |
| MPC, 제약 끔(`u_limit` 0) | 1.58° | 0 |
| MPC, 제약을 모터 피크로(`u_limit` 1.0) | 1.58° | 0 |
| MPC, 선행 없음(`t_lead` 0) | 13.26° | 627 |
| MPC 기본 + 제약의 가정값을 서보 측정 토크로(임시 판) | 1.58° | 36 |

- 차이는 x 1.44~1.62 m(t 7.58~8.22 s, 턱 꼭대기 직전)에서만 생긴다. 그 전까지 두 제어기는 거의 같다. 이 구간에서 왼쪽 다리가 아래 벽(319 mm)에 닿아 있다.
- 걸리는 제약은 **왼쪽 무릎 행**이다(QP 564스텝 중 541). 식은 `0.25 T + 0.25 Tp ≤ 한계 − 가정값`이다.
- 고치기 전 `MpcLaw.limits`의 가정값은 **정적 다리 힘**(35.5 N × 0.192 m = 6.8 N·m)에 벌어짐·요 토크 몫을 더한 8.6~9.4 N·m다. 한계는 9.38 N·m(0.75 × 12.5)라 남는 여유가 0.02~0.8 N·m뿐이다.
- 실제 왼쪽 무릎 토크는 **10.5~12.5 N·m**다. 가정값에는 정적 지지력만 있고, 다리가 범위 끝에 닿았을 때 다리 길이 루프(범위 벽, 서스펜션, 롤)가 더하는 힘이 없다. 한계는 이미 넘었는데 MPC는 그 바로 밑이라고 본다.
- 턱 오르막이라 바퀴 토크 T가 +1.5~+4 N·m 필요하다. 여유가 없으니 QP는 hip 균형 토크를 **음수(−0.2~−2.3 N·m)** 로 민다. 몸통을 세우는 데 필요한 값은 기울기가 커질수록 +0.7에서 +12 N·m까지 올라간다. 몸통은 0.35 s 만에 0.8° → 9.7°로 넘어간다.
- 가정값이 한계를 넘는 순간(t 8.05 s, 9.45 ≥ 9.38) 그 행이 "다른 루프만으로 이미 넘은 제약"으로 빠지고, Tp +8.7 N·m가 나가면서 복귀한다.
- 확인: 가정값을 서보가 보고하는 실제 토크에서 구하면(`가정값 = 측정 토크 − 계수 · 직전 균형 토크`) 그 행이 처음부터 빠져 1.58°가 된다. 10·14 cm 턱은 어느 쪽이든 제약이 걸리지 않아 결과가 같다.

## 5. 2-20(턱 위 속도)과 2-13(날카로운 턱의 옆 이동): 원인과 수정 (2026-11-11)

**원인: 두 항목은 원인이 같다. 울퉁불퉁한 바닥에서 MCU가 속도를 줄일 때, MPC 법칙이 MCU가 넘기는 기울임 값(`v_lean`)을 쓰지 않아 감속이 약했다.**

**수정**: `MpcLaw.compute`가 `LQI8Law`와 같은 식으로 다리 기울기 목표를 옮긴다(`theta -= v_lean · 기준 가속도 / g`). 감속 명령의 선행(0.15 s)은 그대로 두었다. 아래 임시 판 실험에서 선행까지 없애면 2-13의 방향 최대가 기준을 넘었기 때문이다.

| 단계 4 전체, 시드 0 | 고치기 전 | 고친 뒤 | 기준 |
|---|---|---|---|
| 2-20 턱 위 속도 / 감속도 최대 | 0.316 ✗ / 0.33 | 0.180 / 0.60 | ≤ 0.3 m/s / ≤ 1.2 m/s² |
| 2-13 옆 이동 / 방향 최대 | 18.97 ✗ / 14.07° | 16.93 / 14.04° | ≤ 17.5 cm / ≤ 15° |
| 2-12 옆 이동 | 16.65 ✗ | 15.08 ✗ | ≤ 15 cm |
| 2-21 턱 뒤 속도 / 감속도 최대 / 피치 | 1.03 / 0.81 / 3.09° | 0.99 / 0.94 / 3.22° | ≥ 0.8 m/s / ≤ 1.2 / ≤ 4° |
| **2-15 회전 주행의 다리 토크 rms** | 4.98 | **5.03 ✗** | ≤ 5.0 N·m |
| 기준을 넘은 검사 | 10건(시험 7개) | 9건(시험 7개) | |

- 값이 달라진 시험은 MCU의 감속이 걸리는 것들뿐이다(2-7, 2-8, 2-12, 2-13, 2-15, 2-17~2-21). 1-x, 3-x, 4-x는 그대로다.
- **대신 2-15가 기준을 0.5 % 넘게 됐다.** 1 m/s로 가며 2 rad/s로 돌면 좌우 다리 길이가 달라져 MCU의 감속이 걸리는데, MPC가 이제 LQI8만큼 세게 감속하면서 다리 토크가 조금 늘었다. 이 항목은 LQI8도 다섯 시드 모두 4.99 N·m로 기준에 붙어 있다.

아래는 고치기 전의 조사 내용이다.

- 다리 길이가 서로 달라지면 MCU는 속도 기준을 0.2 m/s로 내리고(감속 0.8 m/s², 0.2 s 필터), 균형 법칙에 `v_brake`, `v_brake_tau`, `hold_integrators`, `v_lean`을 넘긴다.
- `LQI8Law`는 `v_lean`으로 다리 기울기 목표를 옮긴다(`theta -= v_lean · 기준 가속도 / g`). 균형 로봇은 뒤로 기울어야 감속할 수 있어서다. 고치기 전 `MpcLaw`는 앞의 세 값만 쓰고 `v_lean`은 쓰지 않았다.
- MPC는 기준이 내려가는 것을 미리 보지만, 비용에서 다리를 뒤로 기울이는 것은 평형에서 벗어난 오차로 계산되고 속도 오차는 값이 싸며 위치 적분은 이 구간에서 멈춰 있다. 그래서 기준보다 늦게 줄인다. 감속도 최대가 0.33 m/s²로 LQI8(0.60)의 절반이다.
- 두 번째 요인은 선행 시간이다. MPC는 모든 속도 명령을 0.15 s 뒤에 따르기 시작하는데, MCU가 스스로 내린 감속 명령도 그만큼 늦게 따른다.
- 토크 제약은 관계없다(2-20에서 QP 0회, 2-13은 제약을 꺼도 같은 값).

- 그래서 기울임 항만 넣었다. 두 항목이 모두 기준 안에 들어온다. 감속 명령의 선행까지 없애면 2-13의 방향 최대가 15.2°로 기준을 넘는다.
- 위 임시 판은 한 시나리오씩만 돌린 것이고, 단계 4 전체는 고친 뒤 다시 돌렸다(이 절 맨 위 표).
