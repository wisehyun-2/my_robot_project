## 1. 구조와 데이터 흐름

```
 사용자 목표: forward v*(목표 속도), left(요 속도), up(높이)            plan.step(v, w) → host.set_command(...) 매 MCU 스텝
        │
        ▼
 ┌──────────────────────── MpcHost (호스트 프로세스, 50 Hz 고정 격자 게시) ─────────────────────────────────────┐
 │ ① 목표 데드밴드(|v*| < 0.02 → 0) → 기준 모델(임계 감쇠 2차): 원하는 응답 v_d(t)(가속 ω 3.5, 감속 ω 10 rad/s)    │
 │ ② 예측 상태 x̂(축약 폐루프 4~5차): 자신이 보낸 r로 전파 + 기동 중에만 텔레메트리 속도로 칼만 보정(혁신 게이트) │
 │ ③ QP(qpmpc 응축 + DAQP, OSQP 백업, warm start): 1.5 s 구간 75단 기준 궤적 → 첫 값 r_0 송신                   │
 │    단계별 가속도 상하한: 로봇 예측 속도와 반대 방향(제동)은 a_dec, 그 외 a_max; 저크 상하한; |r| ≤ v_max         │
 │ ④ 폴백: QP 실패/솔버 없음 → 원시 목표 + host_shaped = False (MCU 1단계 성형), 이벤트 기록, 조건부 복귀         │
 └──────────────────────┬──────────────────────────────────────────────────────────────────────────────────────┘
                        │ link.receive(MotionCtrl(forward = r_0, left = 통과, up = 클립, pitch = roll = leg_split = 0,
                        │                         host_shaped = True), t)
                        ▼
 HostLink (500 ms 타임아웃 → MCU 단절 프로그램, host_shaped = False)   ▲ 텔레메트리 plan.mcu.est: v, v_ref(MCU 자체 기준),
                        ▼                                            │ position, pitch, pitch_rate, theta_v_mean, L0_mean
 MCU 1 kHz / 200 Hz: 추정기 → LQI6(플레인 추종, 기동 중 적분기 동결) → 다리 PD·VMC → 토크
```

- 호스트는 LQI6를 대체하지 않는다. 내려보내는 것은 속도·요·높이 기준뿐이고 피치 기준은 항상 0(`pitch_ctrl_mode = False`), roll·leg_split도 0으로 고정한다(사양 "속도·요·높이만").
- 호스트가 읽는 실행 중 정보는 `plan.mcu.est`(텔레메트리)뿐이다. 모델·이득·MCU 주기·지연은 설계 정보(같은 펌웨어의 이득표, 설정 지연 `latency_ms` — 실기에서는 측정 지연으로 바꿀 것)로 쓴다. 시뮬레이터 상태는 쓰지 않는다(`Plan4UpkieLQI6._obs_to_mcu`가 참값 키를 제거하고, 호스트는 MCU 추정만 본다).
- 정지 중(목표 0이고 기동이 끝난 뒤)에는 기준이 정확히 0이고 보정도 하지 않는다. 그래서 목표 0인 항목(1~7, 9, 10, 12, 15~17)은 1단계와 같은 내부 루프 응답이다(1단계 HostEmulator도 고정 격자 50 Hz로 게시하므로 20번 비교는 같은 호스트 주기에서 이루어진다).
- 사양 범위 검사: 호스트 주기 50~100 Hz, 구간 1~2 s, MCU 주기의 정수배가 아니면 생성 시 `ValueError`(조용히 꺼지지 않음). 내부 폐루프가 불안정하면(지연 ≥ 20 ms) 예측 모델이 무의미하므로 MPC를 끄고 1단계 성형만 쓴다(이벤트).
- 인터페이스(`reference_mpc.MpcHost`): `MpcHost(link, plan, publish_hz=50, horizon_s=None, config=MpcConfig())`; `set_command(**fields)`, `tick(t)`, 속성 `enabled`, `cmd`, `sent`, `violations`, `solve_times_ms`, `qp_failures`, `solver_failures`, `fallback_used`, `force_fail`, `events`, `trace`, `corrections`, `gated_corrections`, `stats()`.

## 2. 예측 모델

### 2.1 선택: (a) 선형 폐루프 축약

플랜트와 이득이 모두 알려져 있으므로(`plan.plant.linearize(L0)`, MCU 이득표) 해석 모델을 쓴다. 비최소 위상(가속하려면 먼저 몸을 앞으로 기울임)과 지연·피치 응답을 그대로 담고, 이득표에서 실행 시점에 다시 만들기 때문에 내부 루프의 이득·구조가 바뀌어도 따라간다. (b) 2차계 피팅은 비최소 위상과 피치를 표현하지 못한다(3~4차 축약과 비교: 아래 표).

### 2.2 기동 영역의 내부 루프 = 적분기 없는 상태 되먹임 (검토 1라운드 M4)

MCU의 LQI6는 호스트 기준이 움직이는 동안 **모든 적분기를 동결**한다(`lqi6.py`: `freeze_int_on_accel_plain`, z_att는 그 전부터 같은 조건으로 게이팅). 그래서 MPC가 예측해야 하는 폐루프는 u = −K_5 [θ, θ̇, v − r, φ, φ̇]의 순수 상태 되먹임 루프다(`model.lqi6_options(ctrl, L0)` → `use_int = False`, `att_gM = None`, `use_pos = False`, `select_gains`가 K의 앞 5열만 쓴다). 적분기를 포함한 모델(1라운드 전)은 가속 중 z_att가 적분한다고 보아 스텝 피치 피크를 1.8° 대 실제 1.0°로 과대 예측했다. 적분기가 다시 켜지는 것은 가속이 끝난 뒤(순항·정지)이고, 그때의 잔류 속도 오차는 MCU의 z가 없앤다(선형 무마찰 모델의 r → v 정상상태 이득은 1.017: 관절 점성 감쇠를 이기는 정상 토크 때문).

구성(`model.py lqi6_closed_loop`): 플랜트 5상태 s = [θ, θ̇, v, φ, φ̇]를 MCU 주기로 ZOH 이산화(`LQI6.design`과 같은 c2d), 측정 e = s_{k−d}(관측 지연 d = 10 ms = 1 kHz 10스텝 / 200 Hz 2스텝), u_k = −K_5[e_θ, e_θ̇, e_v − r_k, e_φ, e_φ̇]. 상태 수 1 kHz 5 + 50 = 55, 200 Hz 5 + 10 = 15. 입력 r(LQI6가 쓰는 기준), F(전체 무게중심 수평 힘, 밀기 검증용), Tf(바퀴 외란 토크). 출력 v(텔레메트리 est.v), v_base(= 판정 vx = v + L0 cos θ_eq θ̇ − h_b φ̇, h_b 0.164 m), pitch(= −φ), θ, T, Tp. 호스트 주기 리프팅(20 ms 동안 r 고정) 뒤 제곱근 균형 절단 + DC 맞춤(채널 가중 r 1 m/s ~ Tf 0.05 N·m, v_base 0.1 m/s ~ 피치 1°), 차수는 단위 스텝 오차가 속도 1 %·피치 0.1° 이하가 되는 최소값 자동 선택.

| 차수 | 3 | 4 | 5 |
|---|---|---|---|
| 1 kHz: v_base / 피치 단위 스텝 rms 오차(전차 대비) | 4.95 % / 0.55° | **0.62 % / 0.046°** | — |
| 200 Hz | 7.59 % / 0.96° | 1.05 % / 0.064° | **0.25 % / 0.018°** |

정지 영역(`regime = "rest"`: 모든 적분기 활성)의 모델은 밀기 응답 비교에만 쓴다(2.3절). MPC는 쓰지 않는다.

## 3. 제약 유도

### 3.1 가속도 한계 a_max (`derive_limits`)

기준 가속도 a(시작 저크 j = a / 0.10 s)의 두 기동을 2.2절의 전차 폐루프 모델(5 ms 분해능)에 넣고 피크를 a의 함수로 구한 뒤 이분법으로 한계를 찾는다. 피치 예산은 모델 오차 계수 1.3으로 나눈다.

| 한계 | 예산(모델 기준) | 1 kHz | 200 Hz |
|---|---|---|---|
| 바퀴 토크 a_T(반전 −1 → +1 m/s) | (1.36 − 정지 중 잡음 토크 0.30) / 질량 +15 % = 0.922 N·m/바퀴 | ≥ 3.2(상한 a_mcu에서 잘림; a = 3에서 0.53 N·m) | ≥ 3.2 |
| 피치(일반, 8·13번) a_p,gen(반전) | (5° − 0.5°) / 1.3 = 3.46° | 2.34 | 2.31 |
| **피치(19번 기동 0 → 0.5) a_p,step** | (2° − 0.5°) / 1.3 = **1.154°** | **0.889** | **0.884** |
| 다리 기울기 a_lean(반전) | 0.8 × 32°(발목 하우징 접촉) = 25.6° | ≥ 3.2 | ≥ 3.2 |
| MCU 램프 a_mcu | 0.8 × 플레인 램프 4 m/s² | 3.2 | 3.2 |

### 3.2 저크 한계

피크는 저크에 둔감하다. 저크 한계의 역할은 50 Hz 계단 기준이 내부 루프 빠른 극(≈17 rad/s, 58 ms)을 흔들지 않게 하는 것이다. a_max까지 오르는 시간 0.10 s(= 1.7 × 58 ms; 1라운드 전 0.15 s): 0.15 → 0.10으로 정지 거리가 5 mm 줄고 피치 피크는 0.03° 안에서 바뀐다.

### 3.3 속도와 다리 길이

- \|r\| ≤ v_max = 1.0 m/s는 **기준**에 대한 제약이다. 전 범위 반전 기동에서 몸체 속도는 기준을 2~6 % 넘을 수 있다(사양의 "속도 한계"를 기준 속도로 해석; 몸체 속도 상한이 필요하면 예측 v̂에 제약을 추가해야 한다 — 보류).
- 다리 길이 범위는 QP 밖에서 처리한다: up을 L_stand + 0.06·up ∈ [0.24, 0.335] m가 되도록 클립(MCU도 같은 범위를 지킨다). 예측 모델은 서는 길이 0.31 m 하나다(웅크린 채 주행은 시험 항목에 없음).

- 제동 피치가 가속 피치보다 작은 이유(계수 1.3을 쓴 가속보다 제동을 더 허용할 수 있는 이유): 순항 중 몸체는 건마찰을 이기려 앞으로 기울어 있고 제동은 그 기울기를 먼저 푼다. 측정으로 정한 값이며 모델에는 없다(`MpcConfig.decel_factor`).
- "제동"의 정의: **기준 가속도가 로봇의 예측 속도와 반대 방향**인 것(`ReferenceQP.stage_bounds`: 직전 계획의 v̂_k 부호로 단계마다 상하한을 둠, |v̂| < 0.02 m/s면 대칭). 기준 r의 부호로 정하면 로봇이 아직 전진하는데 기준이 0을 지나 음수가 되는 순간부터 제동을 풀어야 해 정지가 0.02 m 길어진다. 모드 전환 시의 가능성은 "현재 가속도에서 저크 한계로 도달 가능한 값 아래로는 상한을 내리지 않음"으로 보장한다.
- 판정의 패킷 검사(`acceptance_mpc.packet_violations`, 21번)는 호스트가 보낸 패킷의 Δr/T·ΔΔr/T²를 같은 정의(패킷 시점의 로봇 속도와 반대면 a_dec, 아니면 a_max; 저크 j_max T)로 독립 계수한다.
- **넘김 시점 `obs_hold_s`**(2라운드 검토 M1): 목표가 0이 된 뒤 0.5 s에 예측 상태를 버리고 넘기면 로봇이 아직 0.3 m/s로 구르는 중이어서 그 뒤의 제동 방향을 기준 부호로만 정하게 되고 정지가 약 5 % 길어졌다. 1.0 s로 늘리면 정지 끝까지 보정·예측이 이어진다(정지 −5 %, 제동 피치 +2 %). 제동 계수와 넘김 시간의 격자(위 표의 뒤 세 행)에서 두 주기의 최소 여유가 가장 큰 조합(넘김 1.0 s, 계수 1.15~1.2 사이)을 골라 **1.17**로 두었다. 1라운드 반영판이 "물리적 한계"라고 적은 것은 제동 계수·저크만 쓸어 본 결과였고 틀렸다 — 두 손잡이를 함께 쓰면 전체 매트릭스를 통과하되 여유는 여전히 몇 % 안이다(7절). **3라운드 검토(m2)**: 고정 1.0 s는 0.5 m/s 정지만 덮고 0.8~1.0 m/s 정지에서는 로봇이 아직 0.17~0.37 m/s로 구르는 중에 넘겨, 넘김 뒤 기준 부호로 정한 제동 방향이 실제 진행 방향과 어긋나 몇 패킷이 a_max를 넘었다(0.8 m/s에서 3/2건). 그래서 넘김을 "목표 0이 된 뒤 1.0 s 이상 지났고 텔레메트리 속도 < `obs_hold_v` 0.05 m/s(상한 `obs_hold_max_s` 3 s)"로 바꾸고, 예측이 없을 때(넘김·재동기 직후)의 제동 방향은 기준 부호가 아니라 텔레메트리 속도로 정한다(`ReferenceQP.stage_bounds(v_tel)`). 0.5 m/s 정지에서는 1.0 s에 이미 |v| < 0.05라 판정 결과에는 영향이 없다(7절 r5 결과).
- **한계**: 내부 루프가 기준을 약 0.26 s 늦게 따르므로 0.5 m/s에서 0.13 m는 호스트가 줄일 수 없고, 제동 거리 0.5²/(2·1.04) + 저크 구간 ≈ 0.16 m를 더하면 0.29~0.30 m다. 정지(질량 ×0.85)와 제동 피치(질량 ×1.15)가 반대 방향으로 움직이므로 어느 설정이든 여유는 몇 % 안이다. 제동 계수 1.17은 모델로 유도한 값이 아니라 시험으로 맞춘 값이고(제동 피치의 실측/모델 비 0.65~1.32로 모델이 제동 피치를 예측하지 못함, 2라운드 m2), 정지 뒤 기준은 −0.137 m/s(공칭)까지 역방향으로 내려갔다가 0으로 돌아온다(로봇을 세우기 위한 정상 동작, 2라운드 n3; 넘김 0.5 s 시절에는 −0.09였고, 1.0 s로 늘린 대가로 되돌아감이 0.04 → 최대 0.071 m가 됐다 — 전체 매트릭스 19번 0.050~0.070 / 0.046~0.071 m; 3라운드 M1이 지적한 '−0.09'는 옛 설정의 값이었다). 실기에서 명령 경로 지연 10~20 ms가 더해지면 정지가 0.30~0.31 m로 늘어 19번이 깨진다(2라운드 m7): 예측 모델에 `model_extra_latency_ms`로 넣고 제동 계수를 다시 맞출 것. 이 값은 예측 모델의 **기준 입력에 순수 지연**(MCU 스텝 단위의 지연 사슬 `model.with_input_delay`)으로 들어간다 — 3라운드 검토(m1) 전에는 관측 지연에 더해져 내부 루프 모델의 극이 바뀌었고 10 ms 이상이면 "불안정" 판정으로 MPC가 꺼졌다. 지금은 10·20 ms에서 모델이 안정하고 a_max가 바뀌지 않으며(응답이 그만큼 늦어질 뿐), QP 캐시 키에도 들어간다(`tests/test_plan4_safety.py MpcHostTests`).

## 4. QP 정식화

| 항목 | 내용 |
|---|---|
| 주기 T | 20 ms(50 Hz; 50~100 Hz, MCU 주기의 정수배) |
| 구간 | 1.5 s → N = 75(1~2 s) |
| 결정 변수 | u_k = Δa_k(기준 가속도의 단당 증분), k = 0..74 |
| MPC 상태 ξ_k | [x_k(축약 폐루프 4~5차), s_k(이번 풀이 시점부터의 변위), r_{k−1}, a_{k−1}] |
| 동역학 | a_k = a_{k−1} + u_k, r_k = r_{k−1} + T a_k, x_{k+1} = A_r x_k + B_r r_k, s_{k+1} = s_k + T v̂_k |
| 비용 | Σ_k w_v (v̂_base,k − v_d,k)² + w_p (p̂_k − p_ss)² + w_r (r_k − v_d,k)² + w_a a_k² + w_u u_k² + 종단(마지막 단 ×20) |
| 가중 | w_v = 1/0.05², w_p = 1/(1°)², w_r = 1/0.5², w_a = 1, w_u = 1 |

| 제약 | \|r_k\| ≤ 1.0, 단계별 가속도 상하한(3.4절: 제동 a_dec / 그 외 a_max, 모드 전환 시 저크 도달 가능 한계), \|u_k\| ≤ j_max T |
| 크기 | 변수 75, 부등식 300(r·a 상하 4 × 75) + 변수 상하한 150 |
| 응축 | qpmpc `MPCProblem/MPCQP`의 Φ, Ψ, G; 출력 가중 비용 P = 2(MᵀWM + w_u I)는 직접 조립. P, G 고정(가속/감속 두 벌), 매 풀이마다 q(x0, v_d)와 h(x0, 단계 상하한) 갱신 |

## 5. 텔레메트리 보정 (검토 1라운드 M1)

- 측정 y = 직전 20 ms 동안의 est.v 평균(σ_v 0.01 m/s), 예측 ŷ = 한 주기 전 예측. 보정 x̂ ← x̂ + A L (y − ŷ), L은 가장 느린 축약 모드 방향의 과정 잡음 σ_z = 0.0005/주기로 정한 정상 상태 칼만 이득(관측기 극 |λ| ≤ 0.912 / 0.913 per 20 ms ≈ 0.22 s; 1라운드 전 σ_z 0.002는 극 0.80으로 텔레메트리를 거의 그대로 따라가는 것이었다).
- **혁신 게이트**: |y − ŷ| > 0.1 m/s이면 모델 오차가 아니라 외란(밀기)으로 보고 보정하지 않는다(`gated_corrections` 집계). 1라운드에서는 주행 중 밀기에 호스트가 기준을 −0.67 m/s까지 흔들었다(LQI6 적분기와 같은 오차를 둘이 적분).
- 보정은 목표가 0이 아닌 동안과 목표가 0이 된 뒤 `obs_hold_s` = 1.0 s까지만(정지가 끝날 때까지; 3.4절); 목표는 데드밴드 0.02 m/s로 정확히 0이 된다(1e−4 m/s 조이스틱 잔류가 보정을 켜 두던 문제). 기동이 끝나면 예측 상태를 0으로 넘긴다(handover). 단계별 제동 방향에 쓰는 예측 속도는 직전 주기의 계획(한 단 지연, 2라운드 n2)이다.
- 적분기 판정: 단위원 위 극이 없고 외란 상태도 없다. 1.5 s 시정수의 강한 바깥 속도 루프였던 1라운드 설정과 달리 0.2 s의 약한 보정이며, 내부 적분기가 기동 중 동결되어 "두 적분기의 싸움"이 구조적으로 없다. 측정(24번: 0.3 m/s 순항 중 0.75 W 밀기): 공칭 정착 MPC 1.91/2.03 s(1 kHz/200 Hz) 대 램프 호스트 1.90/1.99 s, 후진 최대 0.006 m/s(1라운드 0.67 m/s); 2라운드 검토의 9조합 재실험에서도 정착 최대 MPC 2.25 s 대 램프 2.33 s, 후진 ≤ 0.018 m/s.

## 6. 폴백 규칙 (검토 1라운드 M2)

1. **전환**: 매 주기 DAQP, 실패하면 같은 주기 OSQP(10 ms 제한). 둘 다 실패·비가용·`force_fail`이면 그 주기부터 **원시 목표 + `host_shaped = False`**를 보낸다 → MCU가 1단계 성형(램프 2 m/s² + 전치 필터 0.3 s + 적분 동결)으로 추종. 이벤트 "fallback engaged: raw target handed to the MCU's stage-1 shaping".
2. **복귀**: 폴백 1 s 이상 지났고, 내부 램프의 가속도 |a| < 0.05 m/s², |측정 속도 − 목표| < 0.1 m/s, `force_fail` 아님 → MCU 텔레메트리 `est.v_ref`(MCU 자체 기준)로 예측 상태를 재동기(무충격)하고 QP를 다시 푼다. 성공하면 "MPC resumed". 1라운드의 조건 |a| < 1e−6은 잡음 때문에 성립하지 않아 복귀가 없었다.
3. **기동 중 실패**(23번 변형): 속도 스텝 중 0.8 s(가속)·1.2 s(목표 근처)·3.04 s(제동)에 0.1 s 강제 실패 → MCU 성형으로 넘어가도 적분기가 동결되어 있어 혼합 과도가 없다(8번 통과), 약 1.8~2.2 s에 MPC 복귀(0.8·1.2 s 실패, 공칭, 두 주기; 3.04 s 제동 중 실패는 정지가 끝난 4.8 s에 복귀. 2라운드 검토의 실패 시각 확장 90회도 모두 8번 통과·복귀). 7절 23번.
4. 내부 폐루프가 불안정(지연 ≥ 20 ms)하거나 모델을 못 만들면 MPC를 끄고 1단계 성형만(이벤트).

- **19번의 얇은 여유**(3.4절): 정지 최대 이탈 ≤ 0.3 m와 피치 ≤ 2°를 질량 ±15 % 전부에서 동시에 지키는 여유가 몇 % 안이다(튜닝으로 통과). 정지 거리를 끝점 기준으로 읽거나 질량 범위·정지 거리 기준을 바꾸는 선택지는 사용자가 택하지 않았다(최대 이탈·base 원점 유지). 여유를 넓히려면 내부 루프의 속도 응답을 빨리 하는 재설계가 필요한데 바퀴 토크 여유가 다른 항목에서 먼저 막힌다.
- **20번 비교 단위**(2라운드 M2, 8절): 항목별 가장 빠듯한 지표로는 회귀 0이지만 지표별로는 8·13번 정지 최대 이탈이 26~27 %, 8번 피치·바퀴 피크 ~20 % 나빠진다(MPC가 19번 피치를 지키려 더 부드럽게 제동). 지표별 해석을 택하면 19·20을 동시에 만족할 수 없다 — 사용자 결정으로 항목 기준을 유지하고 지표별 악화는 기록만 한다.
- **일시 QP 실패 뒤 1 s**(2라운드 m5): 폴백 중에는 MCU 1단계 성형(2 m/s² 램프, 피치 ≤ 5° 기준)이 돌아 질량 극단에서 19번 기준(정지 0.31 m, 피치 2.1~2.3°)은 넘는다. 23번 판정(8번 기준)에는 영향이 없고, 폴백은 8번 등급으로 설계된 것이다.
- **OSQP 백업**(2라운드 m1): `ReferenceQP.solve`의 시간 제한이 잘못된 속성을 참조해 1라운드 반영판에서는 백업이 한 번도 실행되지 않았다(고침). 고친 뒤의 그림자 측정(22번 시나리오의 QP 750회를 OSQP로도 풀어 봄, 3라운드 검토): 10 ms 제한 안에 99.6~99.7 % 수렴, p99 6.4 / 7.2 ms, 최대 11.8 ms — 미수렴은 스텝·제동 시작 순간에 몰리는데 그 순간이 DAQP가 실패할 만한 순간과 겹칠 수 있다는 점이 한계다(미수렴이면 폴백 → 복귀). DAQP를 강제로 실패시킨 12회 중 11회는 OSQP가 같은 주기에 풀었다. DAQP 실패 자체가 0회라 판정에는 영향이 없다. 2라운드 반영판 문서의 "90 %만 수렴(p99 11 ms)"은 틀린 값이었다(3라운드 M1).
- 높이 변화(L0 0.24~0.335 m)에 따른 모델 스케줄링은 없다(서는 길이 0.31 m 하나).
- 몸체 속도 상한(기준 상한만 있음, 3.3절).
- 실기: 텔레메트리가 50 Hz 단일 표본이면 σ_v와 혁신 게이트를 다시 정한다; 예측 모델의 지연을 측정값으로; `est.v_ref`를 텔레메트리에 실어 보낼 것(HANDOFF 2.1).
- 건마찰을 모델에 구조적으로 넣는 것(피치 모델 오차 계수 1.3이 대신한다).
- **적분기 동결 유지 0.1 s의 범위**(3라운드 m3): 제동→복귀의 가속도 부호 교차(간격 41~45 ms)는 덮어 90/90에서 z·z_att·z_pos가 불변이지만, 가속 끝의 교차(간격 121~165 ms)는 유지가 끝난 뒤 20~65 ms 적분한다(|Δz| ≤ 1.9e−3, 해제 순간 속도 오차 ≤ 0.047 m/s). 효과가 작아 그대로 두었다 — 유지 시간을 0.2 s로 늘리면 1단계 z2 동결에도 걸려 두 단계 전체를 다시 맞춰야 한다(19번 여유 1 %). "기동 중 적분기 전부 동결"은 이 범위 안에서의 서술이다.
