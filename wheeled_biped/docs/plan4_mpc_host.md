# Plan 4 2단계: 호스트 MPC 기준 생성기

작성 2026-10-23. 대상: Plan 4(upkie 하드웨어 + LQI6 + DIABLO식 호스트/MCU 분리)의 호스트 쪽 MPC 기준 생성기. 기존 `HostEmulator` 자리에 들어가 MCU의 LQI6 균형기 위에서 속도 기준만 만든다. 코드는 `wbr/controllers/mpc_host/`(`model.py` 예측 모델, `reference_mpc.py` MpcHost·QP·한계 유도·관측기·폴백, `fallback.py` 1단계 성형, `identify.py` 모델 검증, `compare_hosts.py` 비교 그림, `regression.py` 20번 비교), 합격 시험 연결은 `wbr/bench/acceptance_mpc.py`, 결과는 `results/acceptance/plan4_mpc_<rate>Hz.md|json`과 `results/plan4_mpc/`, 모델은 `models/upkie_plan4/plan4_closed_loop.json`.

```
python -m wbr.bench.acceptance --host mpc --stage2 --rate both --matrix reduced --seeds 2 --tag mpc_r1 --jobs 6
python -m wbr.controllers.mpc_host.identify          # 모델 검증 → models/upkie_plan4/plan4_closed_loop.json, results/plan4_mpc/model_fit.png
python -m wbr.controllers.mpc_host.compare_hosts     # 1단계 램프 vs MPC → results/plan4_mpc/ramp_vs_mpc.png
python -m wbr.controllers.mpc_host.regression --stage1 results/acceptance --stage2 results/acceptance
```

> ## 최종 상태 (2026-10-23, 조정자 갱신) — 이 절이 아래 본문보다 우선한다
>
> 본문(1~10절)은 MPC 에이전트가 구현 중에 쓴 설계 기록이다. 그 뒤 조정자가 내부 루프와 인터페이스를 바꿔 10절의 요청 1~4를 모두 해결했고, 전체 매트릭스(9조합 × 5시드 × 2주기, 1360회, 433 s, 코드 해시 c0d681a94d)를 돌렸다. 본문의 "시점 A/B/C" 수치와 19번 실패·폴백 설명(5절 마지막 단락, 9절, 10절)은 **이 절로 대체**된다.
>
> **해결된 요청**
> 1. 19번 피치: LQI6의 정적 자세 적분 z_att를 **저역통과(0.1 s)한 기준 가속도가 0.1 m/s²를 넘는 동안 멈추도록** 게이팅했다(`att_accel_tau/thresh`). 호스트 기준이 20 ms마다 바뀌는 계단이라 단일 스텝 변화가 아닌 저역통과 가속도를 본다. 19번 피치 2.3° → **0.9~1.2°**(공칭), 전체 매트릭스 최악 1.65°(1 kHz)·1.51°(200 Hz).
> 2. 링크 끊김: `MotionCtrl.host_shaped` 플래그. MPC 호스트는 참으로 보내고 MCU는 플레인 추종(램프 4 m/s², 필터·동결 없음)으로 전환, 타임아웃이면 단절 프로그램의 패킷(플래그 거짓)으로 **1단계 성형(램프 2 + 전치 필터 0.3 s + 적분 동결)** 에 돌아간다. 11번 정지 2.86~2.92 s → **2.15~2.36 s**.
> 3. 폴백 인터페이스: QP 실패·비가용(`fallback` 모드)이면 호스트가 **원시 목표 속도를 플래그 거짓으로** 보내 MCU가 1단계 성형을 수행한다(사양 그대로). 본문 5절의 "무제약 해 + 램프 제한기"는 호스트 내부 상태 전파용으로만 남아 있고 송신값에는 쓰이지 않는다. 23번(솔버 강제 실패) 1·8·11 통과(두 주기).
> 4. `acceptance.py`: 23번에 `passes_1_8_11 ≥ 1`, 21번은 `acceptance_mpc.run_constraints`(8·9·13·19의 최악 바퀴 피크·위반 합), 코드 해시에 `model.py`·`fallback.py`·`acceptance_mpc.py` 추가.
>
> 그 밖의 내부 루프 변경(`docs/plan4_lqi6.md` 0절): 5 ms 위치 차분 속도, q_int 0.2·q_v 0.5·r_wheel 0.2·q_pos 0.5, 타원체 타이어. 호스트는 MCU 이득표에서 모델·한계를 실행 시점에 다시 만들므로 코드 수정 없이 따라갔다(`identify.py` 재실행: 속도 스텝 rms 0.026 m/s(5 %), 피치 0.5°, 밀기 0.028 m/s, `results/plan4_mpc/model_fit.png`).

## 1. 구조와 데이터 흐름

```
 사용자 목표: forward v*(목표 속도), left(요 속도), up(높이)            plan.step(v, w) → host.set_command(...) 매 MCU 스텝
        │
        ▼
 ┌──────────────────────── MpcHost (호스트 프로세스, 50 Hz 게시 + 180 ms 하트비트) ───────────────────────────┐
 │ ① 기준 모델(임계 감쇠 2차): v* → 원하는 응답 v_d(t)  (가속 ω 3.5 rad/s, 감속 ω 10 rad/s, 적분 없음)          │
 │ ② 예측 상태 x̂(축약 폐루프 6~7차): 자신이 보낸 r로 전파 + 기동 중에만 텔레메트리 속도로 칼만 보정            │
 │ ③ QP(qpmpc 응축 + DAQP, OSQP 백업, warm start): 1.5 s 구간 75단 기준 궤적 → 첫 값 r_0 송신                   │
 │ ④ 폴백: QP 실패/솔버 없음 → 즉시 무제약 해 + 램프 제한기, 최후 단계 1단계 램프 성형 (이벤트 기록)             │
 └──────────────────────┬──────────────────────────────────────────────────────────────────────────────────────┘
                        │ link.receive(MotionCtrl(forward = r_0, left = 통과, up = 다리 길이 범위로 클립, pitch = 0), t)
                        ▼
 HostLink (500 ms 타임아웃 → MCU 단절 프로그램)                    ▲ 텔레메트리(plan.mcu.est: v, position, pitch,
                        ▼                                           │ pitch_rate, theta_v_mean, L0_mean; 20 ms 평균)
 MCU 1 kHz / 200 Hz: 추정기 → LQI6(적분기 z, z_att) → 다리 PD·VMC → 토크
```

- 호스트는 LQI6를 대체하지 않는다. 내려보내는 것은 속도·요·높이 기준뿐이고, 피치 기준은 항상 0(`pitch_ctrl_mode=False`)이다.
- 시각 규약: `plan.step()`에서 `host.set_command → host.tick(t) → mcu.tick` 순서. 게시는 고정 격자(0, 20, 40 ms …, `next_pub += period`; 부동소수 누적 때문에 HostEmulator는 21 ms 주기가 되는 경우가 있다). 게시한 값은 같은 MCU 스텝부터 쓰인다.
- 호스트가 읽는 실행 중 정보는 `plan.mcu.est`(텔레메트리)뿐이다. 모델·이득·MCU 주기·설정 지연·MCU 램프율은 설계 정보(같은 펌웨어의 이득표, 측정된 지연)로 쓴다. 시뮬레이터 상태(실제 피치, 몸체 속도)는 쓰지 않는다.
- 정지 중(목표 0이고 기동이 끝난 뒤)에는 기준이 정확히 0이고 보정도 하지 않는다. 그래서 목표 속도가 0인 항목(1~7, 9, 10, 12, 15~17)은 1단계와 같은 내부 루프 응답이다(같은 시드에서 수치가 같다, 8절).
- 인터페이스(`reference_mpc.MpcHost`): `MpcHost(link, plan, publish_hz=50, horizon_s=None, config=MpcConfig())`; 속성 `enabled`, `cmd`(요청 MotionCtrl, `forward` = 목표 속도), `sent`(마지막 송신 패킷), `violations`, `solve_times_ms`, `qp_failures`, `solver_failures`, `fallback_used`, `force_fail`, `events`, `trace`, `stats()`. `set_command(**fields)`는 HostEmulator와 같은 의미, `tick(t)`는 매 MCU 스텝.

## 2. 예측 모델

### 2.1 선택: (a) 선형 폐루프 축약

(a)를 택했다.
- 내부 루프는 플랜트와 이득이 모두 알려져 있다(`plan.plant.linearize(L0)`, MCU 이득표 `plan.law.ctrl`). 해석 모델은 이 루프의 세 특징을 그대로 담는다: ① 비최소 위상(가속하려면 먼저 바퀴를 뒤로 돌려 몸을 앞으로 기울임), ② 속도 적분기의 되갚음(MPC 모드는 적분기를 동결하지 않으므로 ∫(v − r)dt가 0으로 돌아와야 하고, 4 m/s² 계단 기준에서 속도가 27~32 % 넘친다), ③ 피치 응답(시점 B에서는 z_att 때문에 속도 변화량에 비례하는 느린 피치 모드까지). (b) 속도 스텝 2차계 피팅은 ①·③을 표현하지 못하고, 아래 표처럼 3~4차로 줄여도 속도 스텝 rms 오차가 5~7 %, 피치 0.7~0.85°다.
- MCU 이득표에서 실행 시점에 다시 만들기 때문에, 다른 에이전트가 이득(q_int, q_att 등)이나 구조(z_att, z_pos, 상태 예측기 `pred_steps`, 엔코더 속도 저역통과 `rate_lpf_tau`)를 바꿔도 따라간다(실제로 01:10의 z_att 추가를 그대로 반영했다).

### 2.2 구성(`model.py`)

1. 플랜트: A(6×6, [θ, θ̇, x, ẋ, φ, φ̇]), B(6×2, [T, Tp]). 위치 x는 제어에 쓰이지 않으므로 5상태 s = [θ, θ̇, v, φ, φ̇]를 MCU 주기 Ts로 ZOH 이산화(`LQI6.design`과 같은 c2d).
2. 제어기: `LQI6.step`의 실행 순서 그대로. 측정 e = s_{k−d}(관측 지연 d 스텝, 10 ms = 1 kHz 10 / 200 Hz 2), z_k = z_{k−1} + Ts(e_v − r_k), z_att,k = z_att,k−1 + Ts(e_θ + e_φ + (Tp_{k−1} − T_{k−1})/gM), u_k = −K[e_θ, e_θ̇, e_v − r_k, e_φ, e_φ̇, z_k, z_att,k]. 지연은 측정 사슬, 직전 출력 u_{k−1}은 상태로 둔다. 선택 사항(현재 꺼짐): z_pos, 상태 예측기(입력 이력 N단), 엔코더 속도 저역통과(필터 상태 2개; 이 모델은 τ ≥ 5 ms에서 폐루프가 불안정하다고 예측했고 시뮬레이션도 10 ms에서 넘어졌다).
3. 입력 r(LQI6가 쓰는 기준), F(전체 무게중심의 수평 힘, 밀기 검증용), Tf(바퀴 외란 토크). 출력 v(= 텔레메트리 est.v), v_base(몸체 원점 속도 = 판정 vx = v + L0 cos θ_eq θ̇ − h_b φ̇, h_b = 0.164 m), pitch(= −φ, 실제 몸체 피치), θ, T, Tp.
4. 상태 수: 시점 B 1 kHz 5 + z + z_att + u_{k−1}(2) + 지연 50 = 59, 200 Hz 19(시점 A는 56/16).
5. 호스트 주기 리프팅(20 ms 동안 r 고정, A_h = A^m, B_h = Σ A^i B). MCU의 4 m/s² 램프는 한 주기의 기준 변화(≤ a_max·T)를 몇 ms 안에 따라가므로 ZOH로 본다.
6. 축약: 제곱근 균형 절단 + 특이 섭동 DC 맞춤(정상 상태 이득 보존). 채널 가중 r 1 m/s ~ Tf 0.05 N·m, v_base 0.1 m/s ~ 피치 1°. 차수는 단위 스텝 오차가 속도 1 %·피치 0.1° 이하가 되는 가장 작은 값을 자동 선택(`MpcConfig.order = 0`).
7. 내부 폐루프가 불안정하면(예: 지연 ≥ 20 ms, 15번 스윕) 예측 모델이 무의미하므로 MPC를 끄고 1단계 램프만 쓴다(이벤트 기록). 모델을 못 만들면(지원하지 않는 LQI6 구조) 같은 처리.

**19번 피치 한계를 a_max에 넣지 않은 이유.** z_att는 가속 중 다리 기울기와 토크를 "정적 몸체 기울기"로 보고 적분하므로, 몸체 피치가 가속도가 아니라 속도 변화량(∫a dt)에 비례한다. 0 → 0.5 m/s의 피치 피크는 a = 0.25에서도 1.28°, 1 m/s² 이상에서 2.0~2.15°로 거의 변하지 않는다. a를 0.33으로 묶으면 피치는 조금만 줄고 90 % 도달이 1.5 s를 넘는다(19번의 "느리게 가서 피치를 맞추는 것 금지"). 그래서 19번 피치는 비용(w_p)에서 다루고 a_max는 일반 한계로 정했다(`MpcConfig.pitch_step_binds`로 바꿀 수 있음). 질량 변동(제어기 공칭)에서 1 m/s² 3 s 지속 가속의 피크는 바퀴 0.196/0.223/0.252 N·m, 피치 5.91/5.60/5.31°(질량 0.85/1.0/1.15)다.

### 3.2 저크 한계 j_max

피크는 저크에 둔감하다(시점 A: 1 m/s² 가속의 피치 피크가 j = 2 → ∞에서 0.36 → 0.42°, 토크는 그대로). 저크 한계의 역할은 기준을 내부 루프 빠른 극(17 rad/s, 58 ms)보다 느리게 바꾸고 50 Hz 계단 기준이 루프를 흔들지 않게 하는 것이다. a_max까지 오르는 시간을 0.15 s(≈ 2.5 × 58 ms)로 두어 j_max = a_max / 0.15 s = 5.55 m/s³(B), 16.2 m/s³(A).

### 3.3 속도와 다리 길이

- \|r\| ≤ v_max = 1.0 m/s(MCU `max_forward`와 같음).
- up은 그대로 통과시키되 위치 모드에서 L_stand + 0.06·up ∈ [L_min, L_max] = [0.24, 0.335] m가 되도록 [−1.17, +0.42]로 클립(높이 속도 모드는 MCU가 범위를 지킨다).

## 4. QP 정식화

| 항목 | 내용 |
|---|---|
| 주기 T | 1/publish_hz = 20 ms(기본 50 Hz; `Plan4Config.host_hz`로 50~100 Hz, MCU 주기의 정수배여야 함) |
| 구간 | horizon_s = 1.5 s → N = 75단(`MpcConfig.horizon_s`, 1~2 s) |
| 결정 변수 | u_k = Δa_k(기준 가속도의 단당 증분, m/s²), k = 0..N−1 → 75개 |
| MPC 상태 ξ_k | [x_k(축약 폐루프), s_k(이번 풀이 시점부터의 변위), r_{k−1}, a_{k−1}] |
| 동역학 | a_k = a_{k−1} + u_k, r_k = r_{k−1} + T a_k, x_{k+1} = A_r x_k + B_r r_k, s_{k+1} = s_k + T v̂_k |
| 비용 | Σ_k w_v (v̂_base,k − v_d,k)² + w_p (p̂_k − p_ss)² + w_r (r_k − v_d,k)² + w_a a_k² + w_u u_k² + 종단(마지막 단 ×20: v̂_N, r_{N−1} → v*, a_{N−1} → 0) |
| 가중 | w_v = 1/0.05², w_p = 1/(1°)², w_r = 1/0.5², w_a = 1, w_u = 1 (속도 5 cm/s ≈ 피치 1° ≈ 기준 편차 0.5 m/s ≈ 가속도 1 m/s²). 감속 구간 변위 가중 w_x는 0(아래) |
| 원하는 응답 v_d | 목표 v*의 임계 감쇠 2차 응답(가속 ω 3.5 rad/s: 모델 90 % 0.97 s / 감속 ω 10 rad/s). 매 주기 현재 상태에서 1.5 s 앞까지 예측 |
| 제약 | \|r_k\| ≤ 1.0 m/s, \|a_k\| ≤ a_max, \|u_k\| ≤ j_max T(상하한) |
| 크기 | 변수 75, 부등식 300행(r·a의 상하 4 × 75) + 변수 상하한 150 |
| 응축 | qpmpc `MPCProblem`/`MPCQP`로 예측 행렬 Φ, Ψ와 제약 G, h(x0)를 만든다. qpmpc의 비용은 상태 전체에 스칼라 가중 하나뿐이라, 출력 가중 비용 P = 2(MᵀWM + w_u I)는 Φ, Ψ로 직접 조립한다. P, G는 고정(가속/감속 두 벌), 매 풀이마다 q(x0, v_d)와 h(x0)만 갱신 |
| 솔버 | qpsolvers + DAQP(밀집 쌍대 능동집합), warm start = 지난 해를 한 단 당긴 primal_start. DAQP 실패 시 같은 주기에 OSQP |
| 적분기 | 없음. 외란·오차 적분 상태가 없고, 정상 상태 오차는 내부 LQI6의 적분기가 없앤다 |

송신값은 최적 기준 궤적의 첫 값 r_0 = r_{−1} + T(a_{−1} + u_0)다. MPC는 내부 루프의 지연·비최소 위상·적분기 되갚음을 예측해 v̂가 v_d를 따르도록 r을 앞당기고, 되갚음 동안에는 목표보다 낮게 유지한다(그림 `ramp_vs_mpc.png` 아래 패널: 0 → 0.5 m/s에서 r은 0.47 m/s까지 오른 뒤 0.33~0.45 m/s로 내려가 있다가 0.5로 수렴).

설계 중 버린 것: 계단 목표 직접 추종(기준 모델 없음)은 모델에서도 기준이 0.72 m/s까지 치솟았다가 0.28로 꺼지는 진동 해를 냈다. 감속 구간 변위 비용 w_x(구간 내 상대 변위, 적분 상태 아님)는 정지 거리 0.22 → 0.19 m에 그치고 뒤로 되돌아가는 속도 −0.13 m/s, 정착 0.95 s로 나빠졌다.

## 5. 폴백 규칙

1. **전환**: 매 주기 DAQP로 풀고 실패하면 같은 주기에 OSQP. 둘 다 해를 못 내거나(비가용·예외·비유한 해) `force_fail`이면 그 주기부터 즉시 폴백, `events`에 기록(`fallback_used`, `qp_failures`; OSQP가 살린 경우는 `solver_failures`만).
2. **폴백 1단계(기본 `fallback_mode="explicit"`)**: 같은 비용의 무제약 최적해 첫 값 u_0 = g·q(x0, v_d)(g = −P⁻¹의 첫 행, 시작 때 한 번 계산, 반복 솔버 없음)를 MPC와 같은 한계의 램프 제한기(\|Δa\| ≤ j_max T, \|a\| ≤ a_max, \|r\| ≤ v_max)에 통과. 예측 상태 전파·텔레메트리 보정은 그대로.
3. **폴백 2단계(최후 또는 `fallback_mode="ramp"`)**: 1단계 성형(2 m/s² 램프 + 가속 중에만 작용하는 0.3 s 1차 전치 필터, 감속은 램프를 따름; `fallback.RampFallback`)을 호스트가 50 Hz로 수행. 1단계 값이 비유한하거나 예측 모델이 무효일 때(내부 폐루프 불안정·모델 생성 실패 → MPC 꺼짐).
4. **복귀**: 폴백 1 s 이상, 기준 가속도 0, `force_fail` 아님 → QP를 다시 풀어 성공하면 MPC로(이벤트 "MPC resumed").

**사양의 "1단계 램프로 전환"을 1단계로 두지 않은 이유.** 1단계에서 이 성형이 8번을 통과한 것은 MCU의 LQI6가 "램프 중 적분기 동결"을 함께 했기 때문이다. MPC 모드의 내부 루프에는 동결이 없어(`freeze_int_on_ramp=False`), 같은 램프를 호스트에서 내보내면 적분기가 가속 중 지연을 쌓았다가 되갚아 속도가 넘친다. 강제 실패(23번) 시험, 시점 A:

|---|---|---|---|---|---|---|---|
| 1단계 램프만 | 1 kHz 공칭 / 0.85·0.5 | 1.03 s | 30.7 % / 30.3 % | 0.123 / 0.119 | **실패** | 통과 | 통과 |
| 1단계 램프만 | 200 Hz 공칭 / 0.85·0.5 | 1.01~1.06 | 28.6 % / 30.0 % | 0.120 / 0.126 | **실패** | 통과 | 통과 |

모델에서도 램프·전치 필터 조합만으로는 (90 % ≤ 1.5 s, 오버슈트 ≤ 20 %, 정상 오차 ≤ 0.05)를 함께 만족하는 값이 없었다(예: 1 m/s² + 0.6 s → 1.50 s·13 %·0.034, 마찰이 있는 시뮬레이션은 더 나쁨). 사양 그대로의 동작(MCU의 1단계 성형으로 돌아가기)을 원하면 MotionCtrl에 "호스트가 성형함" 플래그를 두고 MCU가 폴백 때 1단계 램프·전치 필터·적분기 동결을 다시 켜는 인터페이스가 필요하다(10절 요청 3).

## 10. 남은 과제와 인터페이스 요청

다른 에이전트·조정자 소관(파일을 고치지 않았다):
1. **plan4_upkie_lqi6.py / lqi6.py (19번 피치)**: MPC 모드에서 `q_att`의 z_att가 동적 기울기를 적분해 0.5 m/s 스텝 피치가 2.3~2.4°(1단계도 1.8~1.9°)다. MPC 모드에서 기준 변화 중 z_att 동결, 또는 e_att의 관성 토크 보정 요청. 같은 코드에서 q_att를 끄면 19번 통과(피치 1.53°).
2. **MCU 링크 끊김(11번)**: MPC 모드의 단절 프로그램은 4 m/s² 램프·동결 없는 루프로 서므로 정지 시간이 2.86~2.92 s(기준 3 s, 1단계 2.94~2.99 s로 역시 빠듯). 단절 때 1단계 성형(2 m/s² + 동결)으로 돌아가거나 전용 감속 프로파일을 쓰는 것을 제안.
3. **폴백 인터페이스**: 사양대로 "MCU의 1단계 램프로 전환"하려면 MotionCtrl(예: `mode.host_shaped`)로 MCU가 1단계 성형(램프·전치 필터·적분기 동결)을 다시 켜게 해야 한다. 지금은 호스트 쪽 무제약 해 + 램프 제한기로 23번을 통과시켰다.
4. **acceptance.py**: (a) 23번 판정에 `passes_1_8_11 ≥ 1` 추가(지금은 생존·폴백 사용만 본다; `run_mpc_item`이 값을 낸다), (b) 21번이 속도 스텝만 돌리므로 8·9·13에도 위반 기록을 붙이거나 `acceptance_mpc.constraint_check`를 호출, (c) `code_hash`에 `controllers/mpc_host/model.py`, `fallback.py`, `bench/acceptance_mpc.py`도 넣기(지금은 `reference_mpc.py`만 있어 모델 코드만 바뀌면 캐시가 낡는다).
5. 9·12·15·16·17 실패는 두 호스트에서 수치가 같은 내부 루프 문제다.

MPC 쪽 남은 과제:
- 높이 변화(L0 0.24~0.335 m)에 따른 모델 스케줄링: 지금은 서 있는 길이 0.31 m의 모델 하나를 쓴다(웅크림 중 주행이 없어 시험 항목에는 영향 없음).
- 건마찰을 구조적으로 모델에 넣기(속도 의존 쿨롱 토크를 계획 속도로 근사한 피드포워드는 효과가 작았다). 지금은 적분기 방향 칼만 보정이 흡수한다.
- 1 kHz의 몸체 속도 떨림(노이즈 ±0.03 m/s)이 오버슈트 지표의 절반 이상이다(평균 초과는 0.01 m/s 안). 호스트로는 줄일 수 없다.
- 실기: 텔레메트리 평균·지연이 시뮬레이션 가정(20 ms 평균, 10 ms 지연)과 다르면 관측기 이득(σ_z, σ_v)을 다시 정해야 한다.
- 전체 매트릭스(9조합 × 5시드)는 조정자가 최종 내부 루프로 돌린다. 시점 C(01:28~01:31 수정 뒤) 공칭 점검: 속도 스텝 1 kHz 90 % 1.02 s·오버슈트 1.7 %·피치 2.09°·정지 0.138 m, 200 Hz 1.005 s·2.1 %·2.16°·0.136 m(피치만 2° 초과), 링크 끊김 정지 2.10 s, 22번 p99 0.269 ms, 23번 1·8·11 통과, 0.5 W 밀기는 램프 호스트와 비트 단위로 같음. 호스트 코드 수정 없이 모델·한계·차수가 따라갔다.
