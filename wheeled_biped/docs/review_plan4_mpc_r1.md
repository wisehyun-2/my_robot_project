## 3. 예측 모델 검토

### 3.1 유도의 정확성

`model.lqi6_closed_loop`를 `lqi6.py`의 실행 순서와 한 줄씩 대조했다.
- 플랜트: `plan.plant.linearize(L0)`에서 x를 뺀 5상태를 MCU 주기로 ZOH 이산화 — `LQI6.design`과 같다. 밀기 입력 열(전체 무게중심 수평 힘)도 맞다.
- 제어기: 이득은 MCU의 이득표(`_gains_no_side_effect`, 같은 보간), 적분 z(∫(v − r)), z_att(θ + φ + (Tp − T)/gM, 직전 출력 사용), z_pos(∫z)의 갱신 순서와 부호가 `LQI6.step`과 같다. 관측 지연 10 ms = 10 / 2 스텝(플랜의 `ObservationDelay`와 같은 값)을 측정 사슬로 둔 것도 맞다.
- 리프팅(A^m, ΣA^iB)과 제곱근 균형 절단 + 특이 섭동 DC 맞춤도 맞다. 자동 차수는 두 주기 모두 7차.
- 내 복제본(`spot_check_19.py`의 `closed_loop_gated`, 게이팅 끔)이 저장소 모델과 2e-15 안에서 같다.

모델에 없는 것: **z_att 게이팅**(저역통과 기준 가속도 > 0.1 m/s² 동안 적분 정지, lqi6.py:224-246 — model.py:127 주석 "conditional integration … not modelled"), 5 ms 위치 차분 속도의 추가 지연(약 2.5 ms), MCU 4 m/s² 램프(ZOH로 봄), 포화·적분 클램프, 관절 건마찰과 마찰 보상. 이 중 게이팅이 결정적이다.

### 3.4 텔레메트리 보정은 숨은 적분기인가

`host_analysis.py`: 무제약 MPC 법칙(u₀ = g₀·q(x₀), 목표 0)과 정상상태 칼만 보정(x̂ ← x̂ + A L (y − ŷ))을 합쳐, 측정 속도 y에서 송신 기준 r까지의 호스트를 선형 제어기로 놓고 극과 DC 이득을 구했다.

| | 1 kHz | 200 Hz |
|---|---|---|
| 축약 모델 최대 |고윳값| (20 ms) | 0.9865 | 0.9864 |
| 관측기 오차 극 최대 | 0.9858 | 0.9858 |
| 호스트 제어기(y → r) 최대 |극| / 시정수 | 0.9871 / 1.55 s | 0.9872 / 1.56 s |
| DC 이득 y → r | **−1.57** | **−1.54** |

- 형식 판정: 단위원 위 극이 없고 DC 이득이 유한하므로 **적분기는 아니다**(외란 상태도 없음).
- 동특성 판정: 1.5 s 시정수에 DC 이득 −1.57이므로, 기동 시간 규모(1~3 s)에서는 측정-예측 속도 차를 적분하듯 기준을 움직이는 강한 바깥 속도 루프다. 보정 방향은 LQI6 속도 적분기 z의 방향이라, 밀기처럼 모델에 없는 외란이 생기면 호스트가 그것을 "적분기 와인드업"으로 읽고 기준을 크게 움직인다. 0.3 m/s 주행 중 0.75 W 밀기(1 kHz, m×1.15 μ0.75)에서 기준은 0.28 → −0.003(3.5 s) → 0.51(4.3 s) → 0.16(5.0 s) → 0.33 m/s로 흔들리고 로봇은 −0.29 m/s까지 후진했다(램프 호스트: 기준 0.30 고정, 최저 −0.02 m/s). 사양이 "MPC에는 적분기를 두지 않는다"로 막으려던 "두 적분기의 싸움"이 외란 때 그대로 나타난다(M1).
- 정지 중(목표 정확히 0이고 기동 종료 0.5 s 뒤)에는 보정이 꺼져 이 문제가 없다. 그래서 배터리의 외란 항목에서는 보이지 않는다.

- **m11** 실기 이식 가정이 코드에 없다: 호스트는 같은 프로세스의 `plan.mcu.est` 객체를 MCU 주기로 읽는다(reference_mpc.py:656-659). DIABLO 텔레메트리는 50 Hz다. 이번에 50 Hz 단일 표본·텔레메트리 20 ms 지연·명령 10~20 ms 지연을 넣어 보았는데 19번 지표는 모두 통과했다(6절). 다만 관측기 σ_v(0.01 m/s, 20 ms 평균 가정)는 단일 표본 잡음에 맞지 않으므로 실기 텔레메트리 형식을 정한 뒤 다시 정해야 한다.

- **n1** 본문 2.3·3.1·7.1절 수치가 낡았다(차수 1 kHz 6차 → 7차, a_max 0.833/0.848 → 0.835/0.834, a_lean ≥ 3.2/3.11 → 2.46, a_mcu 3.2 → 합격 시험 1.6). 최종 상태 절이 "대체한다"고 했지만 이 값들은 다시 적지 않았다.
- **n2** 풀이 시간은 `solve_problem` 호출만 잰다(reference_mpc.py:510, 523-525): q·h 빌드, 예외로 끝난 솔버 시간이 빠진다. 호스트 주기 전체는 p99 0.36~0.40 ms(1.4절, 세 경우)라 결론은 같다.
- **n3** 문서의 "목표가 0인 항목은 두 호스트 수치가 완전히 같다"는 10번 1 kHz에서 틀리다(m9).
- **n4** `horizon_s`·`host_hz` 범위 검사가 없고, 호스트 주기가 MCU 주기의 정수배가 아니면 `ValueError`가 잡혀 MPC가 조용히 꺼진다(reference_mpc.py:154-155, 576-579; 이벤트만 남음).
- **n5** `_send`가 `roll`·`leg_split`·`mode_mark`·나머지 모드 비트를 사용자 명령 그대로 통과시킨다(reference_mpc.py:881). 사양("속도·요·높이만")보다 넓다(기본값 0이라 실해 없음).
- **n6** 예측 모델이 시뮬레이션의 설정 지연 `plan.cfg.latency_ms`를 "측정된 지연"으로 쓴다(model.py:318-319). 15번 지연 스윕에서는 호스트가 매 실행의 참 지연을 안다(목표 0이라 영향 없음). 실기에서는 측정값으로 바꿔야 한다.
- **n7** LQI6의 성형 상태(`shaping_on`)가 `plan.reset()`에서 초기화되지 않는다(lqi6.py:111-120). 첫 MCU 틱에서 호스트 플래그가 바로 덮어써서 지금은 무해하지만 `_plan_key`·`derive_limits`가 직전 실행의 램프 값을 읽는다(m1과 같은 경로).

## 7. 권고(우선순위)

1. **M2**: 폴백 전환을 무충격으로(기동 중에는 호스트 성형 유지 또는 MCU 적분기 재정렬) 바꾸고 복귀 조건을 잡음 수준 허용으로 고친 뒤, 23번에 가속·등속·제동 중 실패 변형을 넣어 재판정.
2. **M1**: 목표 데드밴드 + 관측기 혁신 게이팅. 배터리에 "주행 중 밀기"·"목표 1e-4" 변형을 추가하고 1단계 램프 호스트와 비교(6번 정착 4 s 기준 포함).
3. **M3**: 정지 거리 정의를 최대 이탈(+ 되돌아감 상한)로 바꿀지 사용자에게 확인받고, 바꾸면 넘김·감속 기준 모델을 다시 조정해 8·13·19·20 재판정.
4. **M4**: 예측 모델에 z_att 게이팅 반영, MPC 구동 응답으로 피치 채널 검증, a_max 재유도(m1의 램프 값도 함께 수정).
5. **M5**: 최종 해시로 `identify`·`compare_hosts`·`regression`·`acceptance_mpc` 산출물 재생성, 최종 상태 절 수치 정정(19번 최악 1.172°/1.292°, 6번 10회 등), 산출물에 코드 해시 기록.
6. minor: m8(OSQP 시간 예산), m4(패킷 기준 위반 계수), m7(20번을 배터리에 편입하고 실행 단위 비교), m5(이벤트 문구), m9(1단계 호스트 게시 격자를 고정 격자로 맞춘 비교), m10·m11(실기 텔레메트리 형식 확정 후 관측기 재조정).
