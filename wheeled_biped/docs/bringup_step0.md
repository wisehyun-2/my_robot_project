# 0단계 실기 설정 순서와 시험 절차

v5 로봇(링크 25 cm, AKE60-8 × 6, moteus r4.11, pi3hat) 기준이다. 명령과 설정 이름은 `references/moteus`(aec0333)와 `references/pi3hat`(12ab9af)에서 확인했다. **실물에서 돌려 본 절차는 아니다.** 기대값은 시뮬레이션과 코드에서 나온 값이고, "후보"는 아직 정하지 않은 값이다.

## 1. 규약

- 로봇의 앞은 **로커 스위치 쪽**(CAD −x)이다. +x 앞, +y 왼쪽, +z 위다.
- 부품 이름도 로봇 기준이다(2026-11-08 `v5run.rename_to_robot()`, 허브 버전 11부터). `_L` 부품이 로봇 왼쪽(CAD −y), `shell_front`가 스위치 쪽이다. 허브 버전 10 이하의 파일만 옛 이름(`_R`이 로봇 왼쪽)이다.
- 모든 각도와 토크는 **로봇 왼쪽에서 보아 반시계가 +**다. 오른쪽 관절도 왼쪽에서 보고 판정한다.
- 토크는 자식 링크에 작용하는 값이다.
- 단위: moteus는 회전(rev), 코드는 rad, pi3hat은 도/초(dps)다.

## 2. 후보 ID와 배선

upkie와 같은 배치를 후보로 둔다. 다른 배치로 정하면 아래 명령의 ID와 `--pi3hat-cfg`도 바꾼다.

| 관절 | 왼쪽 ID | 오른쪽 ID |
|---|---|---|
| hip | 1 | 4 |
| 무릎 | 2 | 5 |
| 바퀴 | 3 | 6 |

왼쪽은 JC1, 오른쪽은 JC3에 연결한다(`"1=1,2,3;3=4,5,6"`). 옛 v4 배선 코드의 JC1은 앞 방향이 바뀌어 로봇 오른쪽이 되므로 쓰지 않는다.

```bash
sudo python3 -m moteus_gui.tview --pi3hat-cfg "1=1,2,3;3=4,5,6" -t 1,2,3,4,5,6
```

아래의 `1>...` 명령은 tview 아래쪽 터미널에 입력한다. `1>`은 ID 1로 보낸다는 뜻이다.

이 순서를 바꾸지 않는다. 오프셋이 부호에 묶여 저장되므로(`fw/board_debug.cc:855`), 부호를 나중에 바꾸면 영점이 틀어진다.

| 4 | 감속비 | `conf set motor_position.rotor_to_output_ratio 0.125` | 안 넣으면 토크가 회전자 기준이라 출력에서 8배 |
| 5 | 관절 조립 | | |

## 4. 모터 부호 시험

**준비:** 로봇을 받침에 고정해 바퀴를 띄운다. 다리는 아래로 늘어뜨리고, 손이 닿지 않는 거리에서 한 관절씩 시험한다. 처음 값은 모두 `output.sign 1`이다.

**명령 예(ID 1):**

```
1>d pos nan 0 1 p0 d0 f0.3 b1 t0.5
1>d stop
```

- `p0 d0`: 위치·속도 게인 없이 토크만 준다.
- `f0.3`: + 토크 0.3 N·m. 움직이지 않으면 0.2씩 올려 1.0까지 시험한다. 그 이상 필요하면 멈추고 원인을 확인한다.
- `1`: 최대 토크 1 N·m.
- `b1`: 아직 위치 한계를 설정하기 전이라 한계를 무시한다.
- `t0.5`: 명령이 끊기면 0.5 s 뒤 시간 초과 상태로 들어간다. 다음 시험 전에 `d stop`을 보낸다.

**+ 토크에 대한 기대 동작** (좌우 같음)

| 관절 | 눈으로 볼 동작 |
|---|---|
| hip | 허벅지 끝이 뒤로 움직임 |
| 무릎 | 정강이 끝이 뒤로 움직임. 무릎을 굽힌 자세에서는 다리가 펴짐 |
| 바퀴 | 바퀴 위쪽이 앞(스위치 쪽)으로 움직임 |

**tview에서 함께 확인할 값:** `servo_stats`의 `position`이 증가, `velocity`가 +, `torque_Nm`이 +. 동작까지 **네 가지가 모두 맞아야** 통과다.

**반대로 돌면:**

```
1>d stop
1>conf set motor_position.output.sign -1
```

다시 시험해서 통과하면 다음 관절로 넘어간다. 좌우를 거울처럼 장착했다면 좌우 부호가 서로 반대로 나오는지도 비교한다.

**기록표**

| ID | 관절 | 최종 sign | 시험 토크 [N·m] | 동작 | position | velocity | torque_Nm |
|---|---|---|---|---|---|---|---|
| 1 | 왼쪽 hip | | | | | | |
| 2 | 왼쪽 무릎 | | | | | | |
| 3 | 왼쪽 바퀴 | | | | | | |
| 4 | 오른쪽 hip | | | | | | |
| 5 | 오른쪽 무릎 | | | | | | |
| 6 | 오른쪽 바퀴 | | | | | | |

## 5. 위치 한계

기본값 ±0.01 회전을 그대로 두면 다음 문제가 생긴다.
- 범위 밖에서 위치 제어를 시작하면 fault 39가 난다.
- 범위를 0.02 회전 넘으면 바깥으로 미는 토크가 0이 된다. 토크만 쓸 때도 마찬가지다(`fw/bldc_servo_control.h:869`). 서 있는 자세의 hip + 토크가 사라지고, 바퀴는 10.8° 돌면 앞으로 미는 토크가 사라진다.

| 관절 | `position_min` | `position_max` | 근거 |
|---|---|---|---|
| hip | −0.05 (후보) | +0.25 (후보) | 다리 범위와 몸통 기울기에서 잡은 값, CAD 간섭 미확인 |
| 무릎 | −0.30 (후보) | −0.05 (후보) | CAD 검사 하한 286 mm가 −0.306, 벽 485 mm가 −0.078, 완전 신장이 0 |
| 바퀴 | NaN | NaN | 계속 돈다 |

```
2>conf set servopos.position_min -0.30
2>conf set servopos.position_max -0.05
3>conf set servopos.position_min nan
3>conf set servopos.position_max nan
```

무릎의 `position_max`는 완전 신장을 줄이는 값싼 보호 장치다. 다만 토크만 줄일 뿐 관성으로 넘어가는 것은 막지 못한다. 후보값은 시뮬레이션으로 검증하지 않았다.

## 6. 엔코더 영점

**정의:** σ1 = 0은 허벅지가 몸통 −z와 나란한 자세, σ2 = 0은 다리를 곧게 편 자세다. σ3는 절대각을 쓰지 않으므로 맞출 필요가 없다.

**영점 저장(조립 후 한 번, 분해하면 다시):** 축 중심을 기준으로 관절각을 아는 지그에 고정하고 그 각도를 회전 단위로 넣는다. 다리를 곧게 펼 필요는 없다(500 mm는 CAD 간섭 검사 범위 밖).

```bash
sudo moteus_tool --pi3hat-cfg "1=1,2,3;3=4,5,6" -t 2 --set-offset -0.1282
```

| 기립 지그(다리 460 mm) 예시 | 도 | 회전 |
|---|---|---|
| σ1 (hip) | +26.57° | +0.0738 |
| σ2 (무릎) | −46.15° | −0.1282 |

**허용 오차(후보):** hip 0.5°, 무릎 1°. 전체 제어기에서 hip 오차 1°는 몸통 기울기 1°, 무릎 오차 1°는 기울기 0.58°와 다리 길이 2.3 mm로 그대로 남는다.

**확인:** 지그를 다른 각도로 바꾸거나 다리 길이를 재서, 읽은 값과 비교한다. L = 500 cos(σ2 / 2) mm다.

## 7. 전원을 켤 때마다 할 일

전원을 켜면 관절각이 ±22.5°로 접혀 읽힌다. 기립 자세는 σ2 −1.2°로 읽혀 코드가 다리를 500 mm로 본다. 이 상태로 arm하면 시뮬레이션에서 0.24 s 만에 넘어졌다.

**`arm()`이 거부하는 경우(2026-11-08부터):** 아래 중 하나라도 걸리면 arm하지 않고, 이유를 `DiabloMcu.arm_refused`에 남긴다.
- 몸통 피치가 3° 이상
- 다리 길이가 326~485 mm 밖. 영점을 안 맞춘 무릎은 |σ2| ≤ 22.5°로 읽혀 다리가 항상 490 mm 이상이므로 여기서 걸린다.
- 다리의 세계 각도가 ±20° 밖. 영점을 안 맞춘 hip은 다리를 45°의 배수만큼 돌려 읽으므로 여기서 걸린다.
- 서보 표본에 `home_state`(레지스터 0x00c)가 있으면 hip·무릎이 2가 아님. 바퀴는 보지 않는다.

이 검사는 마지막 방어선이다. 아래 순서를 그대로 지킨다.

**전원 자세(결정 필요):** 받침으로 지탱한 **기립 자세**를 후보로 둔다. 이때 실제 각도가 다음 범위 안이면 된다. 이 창 안에서는 정확도가 필요 없다.

| 관절 | 기준값 | 허용 범위 |
|---|---|---|
| hip | +0.0738 회전 | +4.1° ~ +49.1° |
| 무릎 | −0.1282 회전 | −68.6° ~ −23.6° (다리 약 413~489 mm) |

**순서:**
1. 받침에 올린 상태로 전원을 켠다.
2. hip과 무릎에 기준값을 보낸다.

   ```
   1>d nearest 0.0738 && 4>d nearest 0.0738 && 2>d nearest -0.1282 && 5>d nearest -0.1282
   ```

3. 네 관절의 홈 상태 레지스터 0x00c가 2인지 확인한다.
4. 다리 길이를 재서 L = 500 cos(σ2 / 2)와 비교한다. 칸을 잘못 잡으면 무릎이 45° 어긋나 바로 드러난다.
5. IMU가 안정된 뒤 받침에서 내려 arm한다.

## 8. IMU 부호 시험

**장착:** hat이 위, CAN 쪽이 로봇 뒤, USB 쪽이 로봇 오른쪽이다. 코드 값은 `R_base_to_imu = diag(−1, −1, 1)`이다.

```bash
sudo pi3hat_tool --attitude-rate 1000 --read-att -r
```

출력은 `rpy=(롤, 피치, 요) dps=(x, y, z)`다. 전원을 켠 뒤 정지 상태로 1분 기다린다.

| 동작 | 기대 rpy | 움직이는 동안 dps | 규약 값 |
|---|---|---|---|
| 수평 | ±180, 0 | 0 근처 | γ = 0 |
| **스위치 쪽 들기 5°** | ±180, **−5** | **y +** | γ = −5°, γ̇ < 0 |
| 스위치 쪽 내리기 5° | ±180, **+5** | y − | γ = +5°, γ̇ > 0 |
| 왼쪽 올리기 4° | 약 176, 0 | x − | 롤 = +4° |
| 위에서 보아 반시계로 돌기 | ±180, 0 | z + | 요 속도 + |

- 이 장착에서는 보드 피치가 γ와 부호가 같고, y축 자이로는 반대다. **정상이다.**
- 요 값은 판정에 쓰지 않는다. 롤이 ±180 근처일 때 수 ° ~ 수십 ° 달라 보일 수 있다.
- **스위치 쪽 들기는 생략하지 않는다.** 보드 방향을 180° 잘못 달거나 상수가 틀리면 FAULT 없이 피치와 자이로가 함께 뒤집혀 다른 방법으로 잡히지 않는다.

**제어기가 쓰는 자세:** pi3hat 자세를 그대로 쓰지 않는다. 보드 자세는 **시작값**으로만 쓰고, 그 뒤로는 MCU 상보 필터(`wbr/observers/body_attitude.py`)가 원시 자이로·가속도와 엔코더로 자세를 구한다. 보드 필터는 가속을 기울기로 읽기 때문이다(1 m/s 출발·정지에서 보드 1.47° 오차, MCU 0.11°, `docs/robot_v5_model.md` 5절). 그래서 Pi 프로그램은 매 주기 `request_attitude_detail`로 바이어스와 가속도까지 받아야 한다.
- 원시 자이로 = `rate_dps − bias_dps`
- 원시 가속도 = `accel_mps2 + 9.81 × conj(q)·(0, 0, −1)`. 뒤 항은 펌웨어 `OrientationToAccel`이고, hat이 위인 정지 상태에서 (0, 0, +1)이다. 물리적인 아래 방향(0, 0, −1)으로 넣으면 부호가 틀린다.
- 가속도나 바이어스에 NaN이 들어오거나, 받던 바이어스가 빠지면 FAULT다. 바이어스를 처음부터 안 보내면 FAULT 없이 보드 요 속도를 쓰고 이벤트를 한 번 남긴다(회전 뒤 요 속도가 남는 경로).

**영점:** 로봇을 수평으로 두고 읽은 피치가 δ이면 `R_base_to_imu`를 diag(−1, −1, 1)·R_y(−δ)로 둘 수 있다. 전체 제어기에서는 IMU 오차 1°가 몸통 기울기에 영향을 주지 않아(시뮬레이션 0.00°) arm 판정과 표시 값에만 의미가 있다.

**바이어스:** x, y축은 보드가 지우므로 평균을 또 빼지 않는다. z축은 코드가 정지 중에 학습한다. 시뮬레이션(바이어스 0.5°/s 가정)에서 전원 후 10 s에 arm하면 30 s 동안 방향이 2.3° 돌았고, 60 s 뒤 arm하면 거의 돌지 않았다.

## 9. 루프 주기 측정

제어 프로그램이 없으므로 지금은 **통신 주기와 지터만** 잰다. 센서에서 토크까지의 지연은 제어 프로그램이 있어야 잴 수 있다.

**프레임 만들기:** 관절마다 토크 0 명령과 상태 질의를 합친 프레임을 만든다.

```python
import math, moteus
c = moteus.Controller(id=1)
cmd = c.make_position(position=math.nan, velocity=0.0, kp_scale=0.0, kd_scale=0.0, feedforward_torque=0.0, query=True)
print(cmd.data.hex())
```

**측정:** 위치 한계를 설정한 뒤, 받침 위에서 6개 모터 전체로 잰다. 형식은 `버스,16진수ID,16진수데이터,r`이고, 응답을 요청하는 ID 1의 프레임 ID는 `8001`이다.

```bash
sudo pi3hat_tool --realtime 3 --attitude-rate 1000 -c "1,8001,<데이터>,r" -c "1,8002,<데이터>,r" -c "1,8003,<데이터>,r" -c "3,8004,<데이터>,r" -c "3,8005,<데이터>,r" -c "3,8006,<데이터>,r" --time-log cycle.txt -r > /dev/null
```

`cycle.txt`의 나노초 값으로 평균 주기, 99 % 값, 최댓값을 계산한다.

**조합:**
- `--read-att` 있음 / 없음. 있으면 보드 자세 주기(1000 Hz)를 기다린다.
- JC1·JC3 / JC1·JC2. JC1·JC2는 같은 프로세서를 쓴다.
- CPU 격리(isolcpus)와 실시간 우선순위를 켠 상태로 잰다.

**이 측정의 한계:**
- 도구가 매 주기 화면에 출력하고 50 µs 쉰다. 그래서 참고값이다.
- 현재 제어 코드는 매 주기 `request_attitude_detail`이 필요하다. 읽기가 42에서 86바이트로 늘어 10 MHz에서 약 35 µs(계산값)가 더 드는데, 이 도구로는 잴 수 없다.

**표본 시각:** MCU는 자세 필터(자이로 적분)를 **표본 시각의 간격**으로 적분한다(2026-11-08부터). 그래서 Pi 프로그램은 표본마다 읽은 시각(단조 시계)을 `time`으로 넘겨야 한다. 시각이 없으면 고정 `dt`로 돌아가는데, 그때는 건너뛴 표본만큼 각도를 잃는다. 시뮬레이션(1 kHz, 기본 지연 3 ms에 표본 나이 0~j ms 무작위, 1 W 밀기, 시드 2개)에서 피치 피크는 다음과 같았다.

| 표본 나이 지터 | 고정 dt(이전) | 표본 시각 간격(지금) |
|---|---|---|
| 없음 | 14.2° | 14.2° |
| 0~2 ms | 19.3° | 14.1° |
| 0~5 ms | 넘어짐 | 13.7° |
| 0~8 ms | 넘어짐 | 14.4° |

위치는 고정 `dt`로 둔다. 속도가 틱 수로 센 위치 차분 창(`vel_window_s`)에서 나오므로, 실제 주기가 틀려도 둘이 상쇄된다. 위치만 시각 간격으로 바꾸면 주기가 25 % 길 때 위치를 23 % 길게 읽었다. 주기 자체가 틀린 경우는 이 수정으로 해결되지 않는다(1.25배에서 여전히 떨림). 그래서 아래 주기 기준은 그대로다.

**기준(후보):** 지터 2 ms 이하, 평균 주기와 `McuParams.dt`의 차이 5 % 이내, 지연 8 ms 이하. 시뮬레이션 근거:
- 지연은 12 ms까지 정상, 13 ms부터 떨림(1 kHz, 속도 창 5 ms).
- 실제 주기가 가정보다 10 % 길 때까지는 정상, 25 % 길면 떨림.

## 10. 통과 조건

- [ ] 6개 관절 모두 + 토크에 반시계로 돌고, 위치·속도·토크 부호가 맞다.
- [ ] 영점 오차가 허용 범위 안이고, 전원을 다시 켠 뒤에도 같은 값으로 읽힌다.
- [ ] 스위치 쪽을 들면 γ < 0, 왼쪽을 올리면 롤 +, 왼쪽으로 돌면 요 속도 +다.
- [ ] 통신 주기와 지터가 기준 안이다.
- [ ] 모든 드라이버 설정 덤프를 저장소에 보관했다.

## 11. 실물에서 확인할 값

- 모터 마찰로 필요한 시험 토크(AKE60-8 백드라이브 0.12 N·m는 가정값).
- `output.sign`이 관절마다 어떤 값이 되는지.
- 위치 한계 후보가 간섭과 주행 범위에 맞는지.
- moteus 속도 신호의 잡음. 시뮬레이션에서 5 ms 위치 차분은 지연 한계를 12 ms로 줄였고(2 ms 창 15 ms, 창 없음 16 ms) 대신 잡음을 줄였다.
- 서 있을 때 무릎 토크가 +인지(시뮬레이션 약 +3.4 N·m).
