# Obsidian Arrange (`/obsidian_arrange`)

Obsidian 마크다운 노트에서 깨지거나 누락된 마크다운 서식(코드 블록, 표, 제목 계층, 인라인 코드 등)을 원본 내용을 훼손하지 않고 깔끔하게 복구·정리하는 스킬입니다.

## 수행 절차

사용자가 지정한 마크다운 파일(단일 파일 또는 여러 파일)을 읽고, 아래 원칙을 순서대로 적용해 수정합니다.

### 1. 원본 내용 및 Obsidian 문법 보존 (최우선 원칙)
- 문서의 설명, 문맥, 코드 로직, 표 데이터 등 **원본 정보는 임의로 삭제하거나 왜곡하지 않습니다.**
- YAML Frontmatter(`--- ... ---`), 위키링크(`[[문서명]]`), 임베드(`![[파일]]`), 콜아웃(`> [!note]`), 태그(`#tag`) 등 Obsidian 고유 문법은 그대로 유지합니다.

### 2. 코드 블록 및 인라인 코드 정리
- 일반 텍스트로 풀려 있는 코드 조각을 찾아 문맥에 맞는 언어 태그(예: `cpp`, `c`, `python`, `bash`, `cmake`, `yaml`, `json`)를 지정한 코드 블록(```` ```언어 ... ``` ````)으로 감쌉니다.
- 이미 열려 있지만 닫히지 않았거나 들여쓰기가 깨진 코드 블록의 여닫는 백틱(```` ``` ````) 쌍을 맞춥니다.
- 코드 블록 **위와 아래에 반드시 빈 줄**을 두어 Obsidian에서 정상 렌더링되도록 합니다.
- 본문이나 표 안에 등장하는 식별자, 키워드, 연산자(`::`), 파일 확장자(`.h`, `.cpp`), 전처리기(`#include`), 명령어 등은 인라인 코드(`` `...` ``)로 감쌉니다.

### 3. 표(Table) 복구 및 정리
- 표 **위와 아래에 반드시 빈 줄**을 확보합니다. (표 바로 위에 제목이나 일반 문장이 붙어 있으면 Obsidian에서 표로 렌더링되지 않을 수 있습니다.)
- 헤더 행, 구분선 행(`| :--- | :--- |` 또는 `|---|---|`), 데이터 행의 파이프(`|`) 및 열 개수를 일치시킵니다.
- 셀 내부의 줄바꿈은 `<br>`로 정리하고, 셀 안에 파이프 문자(`|`)가 값으로 들어간 경우 `\|`로 이스케이프합니다.
- 표 안의 코드나 명령어는 인라인 코드(`` `...` ``)로 감싸 가독성을 높입니다.

### 4. 제목(Heading) 및 목록(List) 구조 정리
- `1. ...`, `2. ...` 형태나 요약/주의사항 섹션처럼 문단 제목 역할을 하는 줄에 적절한 헤딩(`##`, `###`)을 부여합니다.
- 헤딩과 본문 사이, 목록(`-`, `*`, `1.`) 앞뒤에 적절한 빈 줄을 두어 문단 구분이 명확히 렌더링되도록 합니다.

### 5. 문체 통일 (경어체 → 평서체 `~이다` / `~한다`)
- 노트 본문의 경어체(`~합니다`, `~입니다`, `~됩니다`, `~있습니다`, `~하세요` 등)를 간결한 기술 노트용 평서체(`~한다`, `~이다`, `~된다`, `~있다`, `~해야 한다` 등)로 일관되게 변환합니다.
- 변환 시 문장의 의미나 뉘앙스가 바뀌지 않도록 자연스럽게 다듬습니다.
  - 예: `"사용합니다."` → `"사용한다."`, `"방지할 수 있습니다."` → `"방지할 수 있다."`, `"범위 지정 연산자입니다."` → `"범위 지정 연산자이다."`
- 표 셀이나 목록 항목의 서술형 문장도 동일한 평서체로 통일하되, 원래 명사형(예: `"이름 충돌 방지"`)으로 끝나는 항목은 억지로 어미를 붙이지 않고 그대로 둡니다.
- **예외**: 코드 블록 내부의 주석·문자열, 직접 인용문(`"..."` 안의 대사나 원문)은 원형을 보존합니다.

### 6. 최종 점검 및 보고
- 수정된 파일에 닫히지 않은 코드 블록이나 열 수가 어긋난 표가 없는지, 문체 변환이 누락된 경어체가 남아 있지 않은지 확인합니다.
- 수정한 파일의 클릭 가능한 링크와 함께 변경된 서식 및 문체 정리 내역을 간결하게 요약해 보고합니다.
