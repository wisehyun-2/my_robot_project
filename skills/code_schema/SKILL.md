# Code Schema (`/code_schema`)

사용자가 제공한 C 또는 C++ 코드 파일의 전체 구조와 실행 흐름을 하나의 "지도(스키마)"로 먼저 시각화하고, 그 지도를 기준으로 세부 개념과 문단별 기능을 일관되게 설명하는 스킬입니다.

## 수행 절차

먼저 사용자가 지정한 C/C++ 파일(경로 또는 첨부/붙여넣은 코드)을 읽고, 아래 3가지 원칙을 반드시 순서대로 지켜 응답합니다.

### 1. 전체 구조도와 흐름을 담은 단일 스키마(지도) 그리기
- 코드 전체를 한눈에 파악할 수 있도록 **전체 그림(아키텍처 및 실행 흐름 스키마)**을 그립니다.
- 다이어그램(예: `mermaid` `flowchart TD` 또는 직관적인 ASCII 박스/트리 다이어그램)에는 진입점(`main` 또는 공개 API), 주요 클래스/구조체/함수, 데이터 흐름, 분기 및 반복 흐름, 외부 의존성과의 연결을 포함합니다.
- 이후 단계에서 위치를 쉽게 가리킬 수 있도록 각 주요 영역과 흐름 단계에 **고유 번호 또는 라벨**(예: `[1] 초기화`, `[2] 콜백 등록`, `[3] 메인 루프` 또는 `A`, `B`, `C`)을 부여합니다.

### 2. 세부 개념 설명 시 처음 그린 지도를 그대로 활용하기 (새 스키마 생성 금지)
- **핵심 제약**: 세부 로직이나 특정 개념을 설명할 때 **새로운 스키마나 부분 다이어그램을 추가로 그리지 마세요.**
- 반드시 1단계에서 그린 **최초의 전체 스키마(지도)**에 표시된 노드, 라벨, 화살표 경로를 직접 인용하며 설명합니다.
  - 예: *"위 스키마의 `[2] 데이터 수신 -> [3] 버퍼 검증` 경로에서..."*
- 사용자가 후속 질문으로 특정 개념의 세부 동작을 다시 물어보더라도 새 그림을 그리지 말고, 처음 만든 스키마 지도를 기준으로 위치를 짚어가며 설명합니다.

### 3. 스키마 완성 후 코드 문단별 기능 설명
- 전체 스키마와 핵심 흐름 설명이 끝나면, 코드를 논리적인 **문단(블록) 단위**(예: 헤더/전처리부, 전역 변수/매크로/타입 정의, 클래스/구조체 선언, 각 함수 내부의 주요 논리 블록 등)로 나눕니다.
- 위에서 아래로 순서대로 각 문단을 짚으며 다음 내용을 포함해 설명합니다.
  1. **대상 코드 위치/범위** (라인 번호 또는 해당 문단의 핵심 코드 스니펫)
  2. **수행 기능**: 이 문단의 코드가 구체적으로 어떤 동작과 역할을 수행하는지
  3. **지도상 위치**: 1단계 스키마에서 어느 노드/단계(예: `[1]`, `[2]`)에 해당하는지 연결

## 출력 형식 가이드

응답은 가독성을 위해 아래 구조를 따릅니다. (한국어로 응답하며, 사용자가 다른 언어를 요청하면 그에 맞춥니다.)

1. **🗺️ 전체 코드 스키마 (Whole-Code Map)** — 단 하나의 통합 구조/흐름도
2. **🔍 지도 기반 세부 개념 설명** — 새 그림 없이 위 스키마의 라벨/경로를 참조한 핵심 동작 설명
3. **📖 문단별 코드 및 기능 설명** — 코드 순서대로 문단마다 수행 기능과 스키마 위치 매핑
